# Участие в разработке

## Исходники

Канонические исходники находятся в `cfe llm`. Каталог `cf llm` и бинарные
`.cf`/`.cfe` генерируются и не должны попадать в коммиты.

Сохраняйте существующие UUID объектов метаданных. Новые UUID должны быть
уникальными, а новые объекты должны входить в подсистему `LLM` или её дочерние
подсистемы.

## Подготовка изменения

1. Создайте ветку от актуальной `main`.
2. Ограничьте изменение одной задачей.
3. Не добавляйте ключи, токены, адреса рабочей инфраструктуры и данные
   информационных баз.
4. Сохраните лицензионные заголовки заимствованного кода.
5. Обновите документацию при изменении пользовательского поведения.
6. Добавьте или обновите проверки для изменяемого сценария.

## Локальная проверка

```powershell
.\tools\Test-PublicationReadiness.ps1
.\tools\Test-SubsystemCoverage.ps1
```

После статических проверок загрузите расширение в тестовую базу и проверьте
его средствами конфигуратора. Для пользовательских сценариев выполните тест
в тонком и веб-клиенте, если изменение затрагивает клиентский код.

Изменения интеграции с провайдером считаются проверенными только после
успешного ответа реальной модели. Секреты для такого теста остаются за
пределами репозитория и журналов CI.

## Pull request

В описании укажите:

- какую проблему решает изменение;
- какие объекты метаданных и сценарии затронуты;
- как выполнена проверка;
- есть ли миграция данных или изменение прав;
- какие внешние API или лицензии добавлены.

Изменение стороннего кода должно сохранять исходную лицензию, атрибуцию и
ссылку на источник. При добавлении новой зависимости обновите `NOTICE`.
