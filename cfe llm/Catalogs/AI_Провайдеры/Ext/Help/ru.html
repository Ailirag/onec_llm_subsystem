Провайдеры

Провайдер — сервис, который отвечает моделями: Yandex AI, OpenAI, Z.AI, LM Studio, Ollama или любой сервис, совместимый с OpenAI. С провайдера начинается подключение подсистемы.

Как подключить

  1. Создайте провайдера, укажите тип провайдера и отметьте «Активен» — новый провайдер создается выключенным, и выключенный на любой запрос отвечает ошибкой.
  2. Введите API-ключ. Для локального сервера (LM Studio, Ollama) ключ можно оставить пустым.
  3. В таблице «Адреса сервиса» добавьте строку на каждый протокол, которым будете пользоваться: Chat Completions и (или) Responses API — даже если адрес у них общий. Адрес указывается без «/v1» на конце: путь вида v1/chat/completions подсистема допишет сама. Для Z.AI адрес можно не заполнять.
  4. Нажмите «Загрузить модели»: карточка запишется, и откроется список моделей сервиса. Отметьте нужные — они появятся в моделях. Список берется по адресу строки Chat Completions (у Z.AI — из встроенного каталога). Уже загруженные модели не удаляются и не переименовываются.
  5. Укажите модель в сценарии или выберите ее в чате. Протокол (тип API) выбирается там же — у провайдера его нет.

Поля

ПолеЧто задает
Тип провайдераОсобенности обмена: у Yandex, Z.AI и LM Studio они свои, OpenAI, Ollama и «OpenAI-совместимый» работают одинаково. Пусто — тип определяется по названию.
Работает по API провайдераЗаполняйте, только если сервис повторяет API другого провайдера: тип берется у него, а ключ и адреса — из этой карточки. Обычно достаточно поля «Тип провайдера».
API-ключУходит заголовком Authorization: Bearer. Хранится в карточке и виден тому, кто может ее читать, поэтому права на справочник давайте только администраторам.
Адреса сервисаСтрока на каждый тип API. Тип без строки считается неподдерживаемым. Для загрузки моделей нужна строка Chat Completions, для файлов во вложениях — Responses.
Потоков одновременноСколько операций с этим провайдером выполняется одновременно; 0 — одна. Общий предел на всю базу — «Потоков обработки очереди» в настройках подсистемы; действует меньшее из двух.
Запросов очереди за запускСколько запросов очереди (песочница, программные вызовы) брать за один запуск регламентного задания; 0 — без ограничения. Чат, агентов и AI-действия не ограничивает.
Токенов очереди в суткиСколько токенов в сутки можно израсходовать через очередь запросов; 0 — без ограничения. Считается по журналу запросов, поэтому без включенного журнала не срабатывает.
Таймаут запроса к модели, сСколько ждать ответа модели; 0 — общий таймаут из настроек подсистемы, а если и он 0 — 120 секунд.
Чем читать файлы«Авто», «Мультимодально» или «OCR» — по умолчанию для всех сценариев провайдера; сценарий может задать свой способ. Пусто — «Авто». Подробности — в справке сценариев.
Модель для разбора файловМодель этого провайдера, которая читает картинки и документы из вложений. У Yandex при пустом поле модель подберется сама. У других провайдеров без нее картинки и документы разобрать нельзя — будет ошибка; текстовые файлы читает сама 1С. Ограничения размера и числа файлов берутся из возможностей этой модели.

Сохранять ли тексты запросов и ответов — общий флажок в настройках подсистемы, отдельного флажка у провайдера нет.

Файлы и Yandex

Yandex сам извлекает содержимое файла, переданного через Files API: текстовый слой PDF, распознавание сканов и картинок, документы Office. Поэтому файл читает любая модель Yandex. WebP Yandex не читает — используйте PNG или JPEG. Большие файлы (десятки мегабайт) могут не дойти до модели: проверяйте операцию в мониторе.
