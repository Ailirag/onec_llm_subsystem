# Прикладное ядро API 1.1

Цель: вызывать агента из документов и интеграций без создания диалога.
Исходники предназначены для режима совместимости 8.3.17.

## Сценарий

Администратор создает элемент `AI_Сценарии`:

- стабильный код до 50 символов и положительную версию контракта;
- агента, провайдера, модель и тип API по умолчанию;
- необязательную схему ответа JSON;
- необязательный код скомпилированного прикладного обработчика;
- явно разрешенную политику повторов, от 1 до 10 попыток.

Сценарий нужно включить флагом `Активен`. Доступ к агенту проверяется отдельно:
ссылка на сценарий не предоставляет прав к агенту или его профилю данных.
Без ссылки на сценарий допустим старый контракт с явным `КодСценария` и параметрами
агента/провайдера; код обработчика и схема из произвольных входных данных игнорируются.

## Запуск

```bsl
ПараметрыЗапуска = AI_ПубличныйAPI.ПараметрыВыполнения();
ПараметрыЗапуска.Сценарий = Сценарий;
ПараметрыЗапуска.Промт = "Классифицируй товар из прикладного контекста";
ПараметрыЗапуска.Источник = СсылкаДокумента;
ПараметрыЗапуска.ИдемпотентныйКлюч = КлючПрикладногоСобытия;
ПараметрыЗапуска.КонтекстJSON = "{""version"":1,""product"":""Товар""}";
Запуск = AI_ПубличныйAPI.НачатьВыполнение(ПараметрыЗапуска);
```

`Источник` является только входным удобством API и в операции не хранится. Для
устойчивой идентификации прикладного объекта используются `ТипИсточника` и
`КлючИсточника`; для ссылок API заполняет их автоматически, если значения не
заданы. `ПредставлениеИсточника` также вычисляется автоматически и служит для UI.

Для записи внутри транзакции документа установить `ЗапуститьНемедленно = Ложь`.
За запуск после фиксации отвечает опрос API или настроенное регламентное задание
текущего инициатора. Диспетчер не подменяет пользователей администратором.
Начало с немедленным запуском в активной транзакции отклоняется.

Снимок содержит системную инструкцию, температуру, лимит токенов, контракт ответа
и код обработчика. Настройки инструментов, RAG и веб-поиска берутся из агента при
выполнении; доступ к агенту и назначенному профилю перепроверяется.

## Получение Результата

```bsl
Состояние = AI_ПубличныйAPI.ПолучитьСостояние(Запуск.ИдентификаторОперации);
Если Состояние.Финальная И Состояние.Успешно Тогда
    Ответ = Состояние.Результат;
КонецЕсли;
```

Чтение и отмена разрешены только инициатору. Статус включает токены, шаги,
количество попыток, дату следующей попытки, версию контракта, хеш инструкции,
статус и ошибку доставки. `ДанныеОчищены = Истина` означает, что тексты уже удалены
по сроку хранения, но идентификатор и статистика операции сохранены.

## JSON Schema

Поддержаны `object`, `array`, `string`, `number`, `integer`, `boolean`, `null`,
скалярный `enum` и строковое `description`. Для каждого объекта обязательны
`properties`, все поля в `required`, `additionalProperties=false`.
Корень является объектом. `$ref`, объединения типов и другие ключевые слова
отклоняются, а не игнорируются. Глубина ограничена 16 уровнями.

```json
{"type":"object","properties":{"code":{"type":"string"}},"required":["code"],"additionalProperties":false}
```

Схема передается через [Responses text.format](https://aistudio.yandex.ru/en/docs/ai-studio/api/Responses/createResponse)
или [Chat Completions response_format](https://openai.com/index/introducing-structured-outputs-in-the-api/).
Поддержка зависит от модели. Неподдерживаемая схема/API вызывает явную ошибку,
без молчаливого перехода на текст. Результат дополнительно проверяется в 1С.

## Доставка

Статический белый список реализуется в
`AI_ОбработчикиРезультатовПереопределяемый.ОбработатьРезультат`.
Встроенная подсистема позволяет реализовать этот модуль в проекте внедрения.
Для самостоятельного CFE без такой интеграции используйте опрос API.

Метод получает код обработчика, контракт и выходной признак `Обработан`.
Контракт содержит UUID операции и корреляции, сценарий, версию, тип, ключ и
представление источника, JSON-контекст и текст результата. Обработчик запускается
без привилегий, в
транзакции вместе с отметкой доставки. Он не должен управлять транзакцией,
обращаться к модели или выполнять внешние HTTP-действия. Для внешних действий
запишите собственный outbox с UUID операции как ключом идемпотентности.

При ошибке локальные изменения откатываются. Ответ модели остается успешным,
ошибка доступна отдельно. После устранения причины:

```bsl
AI_ПубличныйAPI.ПовторитьДоставку(ИдентификаторОперации);
```

Повтор ставит отдельное задание доставки, не повторяет модель. Гарантии для
произвольных внешних побочных эффектов не заявляются.

## Обратная Связь

```bsl
ИДОценки = AI_ПубличныйAPI.ОценитьРезультат(
    ИдентификаторОперации, "Исправлено", "Уточнен код", ИсправленныйJSON);
Статистика = AI_ПубличныйAPI.ПолучитьСтатистику();
ОшибкиДоставки = AI_ПубличныйAPI.ПолучитьОшибкиДоставки();
ПоследниеОперации = AI_ПубличныйAPI.ПолучитьПоследниеОперации();
```

Решения: `Принято`, `Отклонено`, `Исправлено`. Можно передать UUID оценки последним
параметром для идемпотентной отправки. Тот же UUID с другими данными отклоняется.
Оценки сохраняют оригинальный и исправленный ответ; только собственные успешные
операции доступны для оценки. Статистика и ошибки также ограничены инициатором.
Те же операции доступны пользователю в обработке `Монитор агентских операций`.
Кнопки обратной связи в диалоге в этот серверный срез не входят.

## Хранение И Повторы

- `AI_СрокХраненияОперацийДней`: срок текстов прикладных операций, 0 отключает очистку.
- `AI_СрокХраненияОценокДней`: срок текстов оценок, 0 отключает очистку; вердикты остаются.
- История диалога и двоичные вложения имеют отдельную политику хранения.
- Повторы модели разрешены только явно, при HTTP 429/502/503/504, до инструментов
  и без вложений; неопределенный исход прерванной попытки автоматически не повторяется.
- Лимиты нового диспетчера не ограничивают прямые вызовы клиента и старую очередь.

## Переход Со Старой Очереди

Старый метод `ПоставитьЗапросВОчередь` сохраняет поведение, пока для агента нет
активного сценария с `ИспользоватьДляСтаройОчереди`. После включения один такой
сценарий маршрутизирует новые текстовые вызовы в ядро. Несколько сценариев
для одного агента вызывают ошибку настройки. Обработчик нового сценария нужно
реализовать до включения маршрута: старый callback в нем не вызывается.

Для выбранной старой записи есть серверный метод:

```bsl
ИДОперации = AI_МиграцияОчереди.ПеренестиЗапрос(ИДЗаписиОчереди, Сценарий);
```

Переносятся только новые записи без попыток, принадлежащие инициатору.
Запись без владельца требует третьего параметра `Истина` и роли `AI_ПолныеПрава`;
инициатором операции становится администратор, подтвердивший перенос.
Вложения требуют отдельного адаптера и явно отклоняются. Перенесенная запись
остается со статусом `ПеренесенВЯдро` и UUID новой операции; старый обработчик
не должен ее захватывать. Массовый автоматический перенос не выполняется.
