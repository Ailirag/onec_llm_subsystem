# Стиль кода BSL

**Когда читать:** перед любой правкой или ревью BSL. Форматирование, метрики,
запрещённые конструкции, именование, документирование, типографика, комментарии.

Где размещать код и как строить архитектуру — [architecture.md](architecture.md).
Области модулей — [module-structure.md](module-structure.md).

## Форматирование

- Отступ — **табуляция**, не пробелы.
- Длина строки — до 120 символов, если строку можно перенести корректно. Перенос,
  оставляющий на новой строке одну переменную, не делать.
- Один оператор в строке. Однострочные конструкции со сложной логикой запрещены.
- Внутри условий и циклов — пустая строка до и после блока кода.
- Следовать замечаниям BSL Language Server. Подавлять — только адресно и с
  обоснованием, комментарием `//BSLLS:`.

### Выравнивание

- Группу однотипных присваиваний **в локальные переменные** выравнивать по `=`.
- Присваивание свойств объекта через точку **не выравнивать** — один пробел
  вокруг `=`. Выровненный блок свойств ломается при первом переименовании
  свойства и даёт diff на строках, которые не менялись.

## Метрики качества

| Метрика | Предел | Строгость |
|---|---|---|
| Длина метода | до 200 строк (исключение — тексты запросов) | жёсткий предел |
| Длина метода | больше 100 строк | повод для декомпозиции |
| Вложенность управляющих конструкций | меньше 5 уровней | жёсткий предел |
| Когнитивная сложность | меньше 15 | повод для декомпозиции |
| Количество параметров метода | до 5 (остальное — структурой шестым) | жёсткий предел |

## Запрещённые конструкции и вызовы

- **`?(Условие, Значение1, Значение2)`** — запрещён в любом виде, включая простой
  невложенный случай. Вместо него `Если ... Иначе` или маленькая функция.
  Причина: логика остаётся видимой в пошаговом отладчике и в ревью.
  `[Правило проекта: строже ИТС]`
- **`Попытка ... Исключение`** вокруг чтения и записи в базу — запрещено, кроме
  явного и обоснованного управления транзакцией. Шаблон транзакции —
  [locks.md](locks.md).
- **Пустой обработчик исключения** запрещён: либо запись в журнал, либо
  `ВызватьИсключение`.
- **`ЗаписьЖурналаРегистрации()`** — только если это требование задачи. Когда
  требование есть, как писать — [logging.md](logging.md).
- **`Сообщить()`** для оповещения пользователя — запрещено. На сервере
  `ОбщегоНазначения.СообщитьПользователю`, на клиенте
  `ОбщегоНазначенияКлиент.СообщитьПользователю`. Причина — в
  [anti-patterns.md](anti-patterns.md), раздел «Сообщить() вместо подсистемы
  сообщений».
- **`Выполнить()`** и **`Вычислить()`** — запрещены без крайней необходимости.
- **Учётные данные в коде** (пароли, токены, ключи API) — запрещены.
- **Сравнение булева с `Истина` / `Ложь`** запрещено: использовать само выражение.
- **Обратный порядок сравнения** (`Если 0 = Сумма`) запрещён.
- **`Новый COMОбъект(...)`** — запрещён, если явно не оговорён задачей. Для Excel —
  табличный документ или БСП, не `Excel.Application`.
- **`ТекущаяДата()`** на сервере — запрещена, только `ТекущаяДатаСеанса()`.
  Разбор последствий — [platform-cases.md](platform-cases.md).

Перед использованием метода платформы убедиться, что он существует в версии из
`platformVersion` в `.1c-workflow.json`. Метод из более новой версии без проверки —
дефект, который проявится не у автора.

## Именование

- Имя переменной отражает **бизнес-смысл и роль**. Суффикс типа допустим только
  когда снимает неоднозначность и не превращается в венгерскую нотацию.
- **Венгерская нотация запрещена**: `МассивКонтрагентов`, `ТаблицаДанных` →
  `Контрагенты`, `Данные`.
- **Имена из глобального контекста** (`Документы`, `Справочники`, `Пользователи`,
  `Регистры`, `Метаданные`, `Константы`) не использовать как локальные
  переменные: они перекрывают контекст и ломают чтение кода.
- Префикс `Получить*` в именах функций избегать, когда возвращаемое значение
  очевидно из имени или функция возвращает коллекцию: `Контрагенты()` вместо
  `ПолучитьКонтрагентов()`. Допустим при прямом делегировании вызову платформы и
  при реализации контракта БСП.
- **Булевы — только в положительной форме**: `ПроверкаПройдена`, не
  `ПроверкаНеПройдена`. Отрицание в имени плюс отрицание в условии читается
  неверно даже внимательным читателем.
- **«Магические числа» запрещены** — выносить в именованные переменные или
  константы.
- Перечисление строковых значений — в алфавитном порядке.
- Зарезервированные имена свойств формы нельзя использовать как локальные
  переменные — перечень и последствия в [forms-module.md](forms-module.md).

## Условия и параметры

- Сложное условие (три и более конструкции) выносить в отдельный метод.
- Параметр функции **не использовать как дополнительный выход** — всё наружу через
  возвращаемое значение.
- Дополнительные параметры передавать структурой, собранной функцией-конструктором:

```bsl
Функция ПараметрыЗаполнения() Экспорт

	Параметры = Новый Структура;
	Параметры.Вставить("Дата");
	Параметры.Вставить("Валюта");
	Параметры.Вставить("ПересчитыватьСумму", Истина);

	Возврат Параметры;

КонецФункции
```

## Сборка строк

Составлять строки через `СтрШаблон()`, а не конкатенацией `+`. Исключение —
простое `Префикс + Суффикс`, когда так читается лучше.

Тексты для пользователя — через `НСтр("ru = '...'")` и
`СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку()`.

## Документирование экспортных методов

Обязательно для всех процедур и функций с `Экспорт`, кроме предопределённых
обработчиков:

```bsl
// Возвращает актуальную спецодежду для должности на указанную дату.
//
// Параметры:
//  ДатаДействия - Дата
//  Должность - СправочникСсылка.Должности
//
// Возвращаемое значение:
//  СправочникСсылка.СпецодеждаДляДолжностей
//
Функция АктуальнаяСпецодеждаДляДолжности(ДатаДействия, Должность) Экспорт
```

- Описание начинается с глагола: «Возвращает...», «Проверяет...», «Рассчитывает...».
- Не начинать со слов «Процедура», «Функция» и с имени метода.
- Для параметров-структур описывать ключи через `*`.
- Для массивов указывать тип элемента.

## Типографика

Относится к артефактам 1С: модулям, комментариям в модулях, идентификаторам,
строковым литералам, синонимам и представлениям метаданных, текстам для
пользователя. К markdown-документации проекта не относится.

- **Не использовать букву «ё»** в коде и в текстах конфигурации. Заменять на «е».
  Причина: раскладки в команде и в типовых конфигурациях расходятся, и поиск по
  тексту перестаёт находить.
- **Не использовать длинное тире** `—`, заменять дефисом `-`. Причина:
  расхождение кодировок в инструментах платформы, особенно в журнале регистрации
  и технологическом журнале, превращает его в `?`.
- Кавычки в текстах для пользователя — `«...»`. В строковых литералах — `"..."`.
- Неразрывные пробелы и прочие невидимые символы Unicode в коде не использовать.

## Комментарии

Предпочтение самодокументируемому коду. Комментарий уместен, когда добавляет то,
чего в коде нет: мотивация, нетривиальный алгоритм, ограничение или побочный
эффект, хак платформы, технический долг с номером задачи.

### Так не нужно

```bsl
// Получаем массив контрагентов
Контрагенты = Контрагенты();

// Цикл по строкам таблицы
Для Каждого Строка Из Таблица Цикл

// Возвращаем результат
Возврат Результат;
```

```bsl
//////////////////////////////////////////////////////////////////
// Модуль: ОбщегоНазначения
// Автор: Иванов И.И.
// Дата: 15.03.2024
// История изменений:
//   15.03.2024 - добавлено
//////////////////////////////////////////////////////////////////
```

Декоративные баннеры и шапки модулей с автором и историей изменений запрещены:
это уже хранит Git, а копия в файле расходится с ним и начинает вводить в
заблуждение.

### Так нужно

```bsl
// НДС не начисляется при экспорте, см. ст. 164 НК РФ
Если Контрагент.Резидент И Не Документ.Экспорт Тогда

// Кеш нужен потому, что метод вызывается около 10000 раз при проведении крупных
// накладных и каждый вызов делает запрос к регистру цен.
ИндексЦен = Новый Соответствие;

// Хак: платформа 8.3.23 не возвращает корректный тип в РазделительИБ при первом
// вызове после старта сеанса - повторяем запрос один раз.
Тип = Метаданные.ОбщиеРеквизиты.РазделительИБ.Тип;
Если Тип.Типы().Количество() = 0 Тогда
	Тип = Метаданные.ОбщиеРеквизиты.РазделительИБ.Тип;
КонецЕсли;

// TODO 14752: после перехода на платформу 8.3.25 убрать обходной путь.
```

`TODO` и `FIXME` обязаны содержать ссылку на задачу. Без номера это не долг, а
след, который никто не разберёт.

### Проверка комментария

Перед тем как оставить комментарий, ответить: **что он сообщает читателю такого,
чего не сообщает сам код?** Если ответ «ничего» — удалить.

## Самопроверка после правки

После изменения кода выполнить внутреннее ревью по объёму правки:

- **Локальная правка** — корректность и граничные случаи изменённого фрагмента.
  Плюс блокировки и транзакции, если правка рядом с транзакционным кодом. Полный
  чек-лист на десяти строках не нужен.
- **Полный цикл** — стиль, читаемость, корректность, граничные случаи,
  безопасность, конкурентность, блокировки, транзакции.

Всегда проверять, нет ли уже внешней транзакции (например транзакции записи
объекта), прежде чем открывать свою.

Успешная самопроверка не заменяет фазы `Compile` / `Selfcheck` / `Verify`: она
касается текста, а не исполнения.
