# Права, роли и RLS

**Когда читать:** когда код создаёт или обновляет профили групп доступа, назначает
их пользователям, проверяет права, роли и ограничения на уровне записей.

Относится к конфигурациям на БСП. Именование новых ролей —
[change-markers.md](change-markers.md). RLS регистров —
[registers.md](registers.md). Привилегированный режим в отчётах —
[dcs.md](dcs.md).

## Роль в профиле — ссылка, а не строка

Реквизит табличной части профиля групп доступа, хранящий роль, имеет **ссылочный**
тип на справочник идентификаторов объектов метаданных, а не строковый.

```bsl
// Неправильно: значение молча отбрасывается
НоваяСтрока = Профиль.Роли.Добавить();
НоваяСтрока.Роль = "ПолныеПрава";
```

**Симптом.** `Профиль.Записать()` завершается без ошибки, но в табличной части
оказывается ноль или одна строка вместо ожидаемых N: обработчик записи БСП
отфильтровывает недопустимые значения, а не возбуждает исключение. Отказ выглядит
как успех.

Полное имя роли для поиска идентификатора — `"Роль." + ИмяРоли`.

## Роли расширений лежат в другом справочнике

Объекты расширений — роли, справочники, документы — регистрируются в справочнике
идентификаторов объектов **расширений**, а не метаданных. Поэтому реквизит роли в
профиле имеет составной тип из двух справочников.

Следствие: прямой запрос к справочнику идентификаторов объектов метаданных **не
находит роли расширений**, и профиль молча получает только роли базовой
конфигурации. На конфигурации с расширениями имена разрешать методом БСП, который
покрывает оба справочника:

```bsl
ПолныеИмена = Новый Массив;
Для Каждого ИмяРоли Из ИменаРолей Цикл
	ПолныеИмена.Добавить("Роль." + ИмяРоли);
КонецЦикла;

// Соответствие: полное имя -> ссылка, из метаданных ИЛИ из расширений.
// Второй параметр Ложь: ненайденные пропускаются без исключения.
КартаИдентификаторов = ОбщегоНазначения.ИдентификаторыОбъектовМетаданных(ПолныеИмена, Ложь);
```

Прямой запрос допустим только на конфигурации без расширений — и это условие
перестаёт выполняться в момент, когда в проект добавят первое расширение.

Для одиночной роли метод БСП, принимающий объект метаданных, возвращает ссылку и
**создаёт запись справочника, если её нет** — это нужно сразу после добавления
новой роли в конфигурацию, пока БСП её не зарегистрировала.

**В интерфейсе профиля роли отображаются по синониму, а не по имени.** Фильтр
видимого списка по префиксу имени не находит ничего, если у роли есть человеческий
синоним. Искать по синониму либо заполнять профиль программно.

## Создание и обновление профиля

```bsl
УстановитьПривилегированныйРежим(Истина);

СсылкаПрофиля = Справочники.ПрофилиГруппДоступа.НайтиПоНаименованию(ИмяПрофиля, Истина);

Если СсылкаПрофиля.Пустая() Тогда
	Профиль = Справочники.ПрофилиГруппДоступа.СоздатьЭлемент();
	Профиль.Наименование = ИмяПрофиля;
Иначе
	Профиль = СсылкаПрофиля.ПолучитьОбъект();
	Если Профиль.ПоставляемыйПрофиль Тогда
		ВызватьИсключение НСтр("ru = 'Поставляемый профиль: редактирование запрещено.'");
	КонецЕсли;
КонецЕсли;

Профиль.Роли.Очистить();
НеразрешенныеРоли = 0;

Для Каждого ИмяРоли Из ИменаРолей Цикл

	СсылкаИдентификатора = КартаИдентификаторов.Получить("Роль." + ИмяРоли);

	Если СсылкаИдентификатора = Неопределено Тогда
		НеразрешенныеРоли = НеразрешенныеРоли + 1;
		Продолжить;
	КонецЕсли;

	НоваяСтрока = Профиль.Роли.Добавить();
	НоваяСтрока.Роль = СсылкаИдентификатора;

КонецЦикла;

Если Профиль.Назначение.Количество() = 0 Тогда
	Назначение = Профиль.Назначение.Добавить();
	Назначение.ТипПользователей = Справочники.Пользователи.ПустаяСсылка();
КонецЕсли;

Профиль.Записать();
```

Неразрешённые роли **считать и сообщать**. Молча укороченный список ролей — это
ровно тот отказ, который описан в двух разделах выше, и внешне он неотличим от
успеха.

## Назначение профиля пользователю

Работать через программный интерфейс общего модуля управления доступом:
включение профиля пользователю, отключение профиля (либо всех профилей), полная
переустановка прав по массивам групп доступа и групп пользователей.

- Метода «добавить пользователя в группу» в БСП нет. Назначение — включение
  профиля, полный сброс — переустановка прав.
- Включение профиля рассчитано на **упрощённый** режим настройки прав: оно создаёт
  или находит персональную группу доступа. В обычном режиме работать через группы
  доступа переустановкой прав.

## Проверка прав, ролей и RLS

- Роль конфигурации проверять методом БСП, принимающим имена ролей **строкой через
  запятую**, а не массивом. Платформенный `РольДоступна()` игнорирует
  привилегированный режим и статус полноправного пользователя, поэтому на
  конфигурации БСП использовать методы БСП.
- Проверка роли **в профилях групп доступа** учитывает RLS на чтение — это другая
  проверка, чем «роль конфигурации доступна».
- Проверка права принимает ссылку на объект **данных** (папку файлов и подобное), а
  не объект метаданных. Передача объекта метаданных — ошибка.
- Проверки RLS на уровне записей существуют в двух видах: функции, возвращающие
  булево, и процедуры, возбуждающие исключение при запрете. В стандартном (не
  производительном) варианте RLS передача пользователя, отличного от текущего,
  вызывает исключение — сначала проверять, какой вариант включён.
- Клиентский аналог проверки полных прав существует только для текущего
  пользователя.

## Антипаттерны

| Антипаттерн | Что происходит на самом деле |
|---|---|
| Строка в реквизите роли | значение молча отбрасывается обработчиком БСП, профиль записывается «успешно» с укороченным списком |
| Разрешение ролей прямым запросом на конфигурации с расширениями | роли расширений не находятся, профиль неполный, ошибки нет |
| Признак загрузки обмена данными перед записью профиля | обработчики БСП отключаются: строка профиля записана, но в подсистеме управления доступом не зарегистрирована и кеш прав не перестроен. Профиль существует и не даёт ничего |
| Правка поставляемого профиля | запись удаётся, следующее обновление конфигурации восстанавливает состояние поставщика |
| Сопоставление входных имён ролей с синонимами наивным сравнением | исходные данные (таблицы, документы) содержат синонимы с разным регистром и двойными пробелами; сначала сравнивать по синониму, затем по нормализованной форме |

## Проверка результата

Роль с полными правами обходит RLS и скрывает дефекты ограничений. Любое изменение
ролей и ограничений проверять под неадминистративным пользователем — иначе зелёная
проверка означает только то, что администратор видит всё.
