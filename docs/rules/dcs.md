# Отчёты на СКД

**Когда читать:** при проектировании и ревью отчёта на системе компоновки данных.

Запрос внутри набора данных подчиняется [queries.md](queries.md). Регистры как
источник — [registers.md](registers.md). Журналирование отказа формирования —
[logging.md](logging.md).

## Выбор типа набора данных

| Тип | Когда |
|---|---|
| Запрос | по умолчанию: данные лежат в метаданных, и запрос выражает нужное |
| Объединение | два и более независимых запроса с одинаковым набором колонок (например движения и остатки) |
| Объект | данные вычисляются в BSL (внешняя система, сложная агрегация, таблица, построенная процедурно) и передаются таблицей значений |

Набор типа «объект» теряет проброс отборов и параметров в СУБД: движок получает
таблицу целиком и фильтрует после. Это самая частая причина медленного отчёта.
Использовать только когда запросом задачу выразить нельзя; если данные нужны
повторно — материализовать в регистр сведений.

## Вычисляемое поле, ресурс, поле запроса

Три разных механизма. Выбор — по тому, **когда** значение материализуется, а не по
удобству ввода.

| Механизм | Когда вычисляется | Для чего |
|---|---|---|
| Поле запроса | один раз, при исполнении запроса на СУБД | всё, что СУБД может вычислить сама |
| Ресурс | при агрегации, на итогах движка | величины, которые нужно суммировать, усреднять, считать по группировкам |
| Вычисляемое поле | построчно, после того как запрос вернул строку | построчные производные: представление, склейка, приведение типа, простая арифметика по имеющимся полям |

Порядок предпочтения: **поле запроса → ресурс → вычисляемое поле.** Перенос
вычисления в запрос уменьшает объём строк, который движок передаёт клиенту.

Антипаттерн: агрегация внутри вычисляемого поля через вычисление выражения по
группировке. Это отключает использование индексов и заставляет обходить строки
целиком. Для этого существует ресурс.

`Формат` по умолчанию **не печатает ноль**: `Формат(0, "ЧЦ=4")` даёт пустую
строку. Представление, склеенное из таких кусков, превращается в «ч мин» без
единой цифры, причём числа в соседних колонках остаются верными и дефект по ним
не виден. В каждом числовом куске представления указывать `ЧН=0`.

## Параметры

- **Параметр** привязан к запросу или набору данных; **параметр выбора** — это
  ограничение выбора в поле ввода. Они не взаимозаменяемы.
- Периоды для виртуальных таблиц регистров — **всегда параметрами**, никогда
  литеральными датами в тексте запроса. Литеральная дата в отчёте живёт до первого
  следующего периода и потом даёт неверные, но правдоподобные числа.
- Параметрам, которые вычисляются программно (текущий пользователь, текущая дата),
  снимать признак доступности: пользователь не должен их править.
- Признак использования оставлять автоматическим, кроме параметров, которые
  действительно не могут быть пустыми: тогда движок сможет исключить
  неиспользуемые параметры из плана.
- Параметр, на который ссылается **текст запроса**, помечать используемым ВСЕГДА,
  даже когда значение пустое. Пустая ссылка в условии вида «пусто ИЛИ равно»
  означает «все», а неиспользуемый параметр движок в запрос не передаёт вовсе, и
  компоновка падает с «Не задано значение параметра». Это относится и к параметрам,
  которые проставляет обработчик формирования результата.

## Варианты и настройки

- **Вариант — отдельная форма отчёта**, а не пользовательский отбор. Вариант
  оправдан, когда представления принципиально разные («по документам» и «по
  контрагентам»). Вариант «тот же отчёт с другим отбором по умолчанию» — не вариант,
  а пользовательская настройка.
- **Пользовательских настроек держать минимум.** Каждая настройка — обязательство
  на поддержку. Сокращать поверхность: всё, что не задумано как ручка для
  пользователя, помечать недоступным; для трёх-пяти реально изменяемых полей
  использовать быстрые настройки; для периода и организации задавать автоматическое
  значение, а не пустое.

## Программное формирование

Для непростого отчёта штатный приём — программное переопределение компоновки, а не
отдельный вариант схемы под каждый случай. Точки подключения в порядке
предпочтения:

1. `ПриКомпоновкеРезультата` в модуле объекта отчёта;
2. обработчики загрузки настроек на сервере — программная подстановка отборов и
   параметров при открытии формы;
3. прямая работа с настройками компоновщика.

```bsl
Процедура ПриКомпоновкеРезультата(ДокументРезультат, ПараметрыВывода, СтандартнаяОбработка)

	// Результат формируем сами; штатная компоновка выполняться не должна.
	СтандартнаяОбработка = Ложь;

	КомпоновщикНастроек.ЗагрузитьНастройки(СхемаКомпоновкиДанных.НастройкиПоУмолчанию);
	УстановитьПараметр("Период", ПериодОтчета);
	УстановитьФильтр("Организация", Организация);

	Попытка

		МакетКомпоновки = Новый КомпоновщикМакетаКомпоновкиДанных().Выполнить(
			СхемаКомпоновкиДанных,
			КомпоновщикНастроек.Настройки,
			,
			,
			Тип("ГенераторМакетаКомпоновкиДанных"));

		ПроцессорКомпоновки = Новый ПроцессорКомпоновкиДанных;
		ПроцессорКомпоновки.Инициализировать(МакетКомпоновки);

		ПроцессорВывода = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
		ПроцессорВывода.УстановитьДокумент(ДокументРезультат);
		ПроцессорВывода.Вывести(ПроцессорКомпоновки);

	Исключение

		ДанныеОшибки = Новый Структура;
		ДанныеОшибки.Вставить("Отчет", Метаданные().Имя);
		ДанныеОшибки.Вставить("Период", ПериодОтчета);
		ДанныеОшибки.Вставить("Подробно", ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));

		ЗаписьЖурналаРегистрации(
			"Отчет." + Метаданные().Имя + ".Ошибка",
			УровеньЖурналаРегистрации.Ошибка,
			Метаданные(),
			,
			НСтр("ru = 'Не удалось сформировать отчет.'"),
			ДанныеОшибки);

		ВызватьИсключение;

	КонецПопытки;

КонецПроцедуры
```

Существенные детали шаблона:

- `СтандартнаяОбработка = Ложь` ставится **до** `Попытка`. Если обработчик выйдет
  по исключению посередине формирования, платформа не должна молча выполнить
  штатную компоновку и выдать второй, недоделанный документ.
- Исключение возбуждается снова: иначе вызывающий код считает отчёт
  сформированным.
- Вспомогательные методы установки параметров и фильтров держать в модуле менеджера
  отчёта, чтобы переопределение оставалось коротким и читаемым.

## Проверка отчёта

«Сформировался без ошибки» — не проверка. Пустой результат проходит её так же
успешно, как правильный, и именно так пустой отчёт уезжает пользователю.

Новый отчёт требует трёх вещей сразу, и ни одна не заменяет другие.

1. **Данные на стенде.** Отчёт показывает то, что есть в базе; если подготовка
   данных не знает про его источники, показывать будет нечего. Отчёт, который по
   умолчанию берёт справочник или календарь по имени, требует, чтобы на стенде
   было ровно это имя. Шаг gate `new-objects-have-fixtures` не даёт добавить объект
   метаданных, не тронув подготовку данных (`functionalTests.fixturePaths`).
2. **Проверка содержимого.** Юнит-тест компонует отчёт настоящей схемой
   (`КомпоновщикМакетаКомпоновкиДанных` + генератор для коллекции значений) и
   сверяет ЗНАЧЕНИЯ: и числа, и **текст представлений**. Текст проверять отдельно:
   арифметика бывает верной, а напечатано пусто.
3. **Снимок.** UI-проверка сохраняет снимок сформированного отчёта ВСЕГДА, а не
   только при падении. Стенд после фазы удаляется, и другого способа увидеть, как
   отчёт выглядит, не остаётся.

Проверять содержимое по разбору табличного документа на колонки ненадёжно: разбор
опирается на то, какую строку считать шапкой, а блок параметров над таблицей
сбивает эту догадку. Колонки — предмет юнит-теста, UI-проверке достаточно
убедиться, что строки данных есть, и снять отчёт.

Две ловушки UI-проверки отчёта, каждая стоит прогона вслепую:

- Текст ячеек табличного документа разделён **неразрывными** пробелами (U+00A0).
  Поиск подстроки с обычным пробелом не находит ничего, и оба текста при этом
  выглядят одинаково. Перед сравнением пробелы нормализовать.
- Снимок экрана функция съёмки обычно не сохраняет, а ВОЗВРАЩАЕТ. Вызов без
  записи в файл читается как «снимок сделан» и молча не оставляет ничего.
  Проверять глазами наличие файла, а не наличие вызова.

Периоды по умолчанию делают отчёт зависимым от дня прогона. Данные стенда обязаны
покрывать период по умолчанию целиком, иначе проверка будет падать по календарю,
а не по дефекту.

## Взаимодействие с RLS

- Запросы СКД по умолчанию исполняются под ролями пользователя, и ограничения
  доступа участвующих объектов применяются.
- Если отчёту действительно нужна полная видимость (регламентированная отчётность),
  привилегированный режим включается **только** в обработчике формирования
  результата и всегда снимается — в том числе при исключении. Причина фиксируется
  комментарием рядом.
- Расширять видимость молча нельзя: каждое включение привилегированного режима
  обосновывается в описании отчёта.

## Производительность

- Поля отборов, которые уходят в условие запроса, обязаны попадать в индекс.
- Виртуальные таблицы фильтровать параметрами, не условием после вызова.
- `ПЕРВЫЕ N` для отчётов с постраничным выводом и отчётов «топ-N» — в запрос, а не в
  обработчик формирования строк.
- `ВЫРАЗИТЬ` в левой части условия отключает использование индекса.
- Набор данных типа «объект», тянущий большую таблицу значений из BSL, — первое, на
  что смотреть при разборе медленного отчёта.

Отчёт, формирующийся дольше десяти секунд, выносится в фоновое задание с
индикацией прогресса — [platform-cases.md](platform-cases.md).
