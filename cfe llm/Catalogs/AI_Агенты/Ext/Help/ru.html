Агенты

Агент задает, как ведет себя модель и кому она доступна: системная инструкция, параметры ответа, доступ к данным базы, внешние инструменты и знания. Агент выбирается в чате и в сценарии. Без доступа к агенту пользователь не видит и AI-действий, которые на нем работают.

Основные поля

  • Программный идентификатор — уникальный обязательный код: по нему агента находит код внедрения и обработчик очереди запросов. Модели не передается.
  • Температура — свобода формулировок: 0,1–0,3 для точных ответов и извлечения данных, 0,4–0,7 для свободного текста. Ноль не допускается.
  • Лимит токенов ответа — наибольшая длина ответа; рассуждающие модели тратят его и на скрытые рассуждения. Ноль не допускается.
  • Разбирать ответ как JSON — только для очереди запросов: ответ разбирается и передается обработчику структурой.
  • Агентский режим — модель получает инструменты и работает в несколько шагов: ищет объекты метаданных, составляет и выполняет запросы, вызывает MCP-инструменты. Так дольше и дороже, зато ответ опирается на данные базы. Для чтения данных нужны профиль с разрешенными запросами и роль «Анализ данных агентом» (или «Полные права»). Число шагов ограничивает профиль доступа.
  • Профиль доступа к данным — что агент может читать в агентском режиме, см. профили доступа. Пусто — только обзор метаданных, без данных. Это профиль по умолчанию: в назначениях на вкладке «Доступ» можно указать свой.
  • Профиль внешних MCP-инструментов — какие инструменты внешних серверов разрешены, см. профили MCP. Действует только в агентском режиме.

Вкладки

  • Инструкция — системная инструкция: роль, задачи, стиль и ограничения. Обязательна. В агентском режиме к ней добавляются правила работы с инструментами.
  • Веб-поиск — «Искать в интернете» и список доменов, которыми поиск ограничен (например consultant.ru). Работает только с Responses API и Z.AI, иначе запрос завершится ошибкой; у Yandex поиск включается принудительно. «Объем результатов поиска» (Low, Medium, High) учитывают Yandex и Z.AI; Z.AI берет только первый домен.
  • Доп. контекст — постоянные сведения, которые уходят модели отдельными сообщениями, см. дополнительный контекст.
  • База знаний (RAG) — коллекции, в которых перед ответом ищутся похожие на вопрос фрагменты, и метки доступа, которыми эти фрагменты отбираются. «Лимит фрагментов» — сколько брать из коллекции (0 — ничего); «Вес коллекции» меняет только порядок фрагментов; «Минимальное сходство» — от 0 до 1, 0 — без порога. См. RAG-коллекции.
  • Доступ — кому агент доступен, см. ниже.

Доступ пользователей

Режим доступаКто видит агента
Всем пользователям LLMВсе, кто работает с подсистемой. Назначения в таблицах при этом задают свой профиль данных.
По назначениямПользователи из таблицы «Пользователи» и участники активных групп из таблицы «Группы пользователей». Так создается новый агент: пока таблицы пусты, его не видит никто.
ОтключенНикто, включая назначенных.
  • Пользователя добавляет кнопка «Подобрать пользователя» в панели таблицы; для нее нужны права администратора информационной базы. Доступ проверяется по идентификатору пользователя, поэтому переименование его не снимает.
  • Личное назначение важнее группового. Среди групп действует строка с наибольшим приоритетом. Если группы одного приоритета дают разные профили, доступ блокируется до устранения противоречия. Пустой профиль в строке — профиль агента.
  • В строках учитываются только отмеченные «Активен» и «Активна»; новая строка группы добавляется неотмеченной.
  • Доступ перепроверяется и при выполнении операции: если его отозвали, поставленная операция завершится ошибкой.

Видимость отдельного AI-действия дополнительно сужается в месте запуска, вкладка «Кому показывать».
