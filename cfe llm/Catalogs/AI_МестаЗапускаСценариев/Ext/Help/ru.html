Места запуска сценариев (AI-действия)

Место запуска — это AI-действие, каким его видит пользователь: где оно показывается, что получает модель, что делается с ответом, кому оно видно и какая обработка вмешивается в его ход. Быстрее всего действие заводит мастер «Новое AI-действие»; здесь — ручная настройка и то, чего мастер не умеет.

В списке: название, подпись в помощнике, включено ли, где показывается, объект, сценарий, что делается с результатом, порядок. Кнопка «Новое AI-действие…» открывает мастер на объекте текущей строки.

Карточка места

Проверка настройки

Форма проверяет то, что иначе всплывает только у пользователя — действие просто не видно или отвечает пустотой. Проверка идет при открытии, после записи и по кнопке «Проверить настройку»; проверяется текущее содержимое формы, еще до записи, и сама проверка ничего не записывает:

  • объект не найден в конфигурации, место или сценарий выключены, карта выключена или настроена на другой объект;
  • схема ответа в сценарии отстает от карты — кнопка «Обновить схему сценария»;
  • обработка помощника не зарегистрирована в дополнительных обработках или не назначена на объект — кнопка «Подключить команду к объекту»;
  • для методов этапов не выбрана внешняя обработка или ее нет в реестре, имя метода недопустимо;
  • условие «Кому показывать» не выполнится ни у кого;
  • у вопроса не найден источник вариантов или нет связи с объектом, пачка с «Заполнить форму», разговор вместе с пачкой, обновление строк по номеру без данных объекта.

Где показывать

  • В карточке объекта — в AI-помощнике из карточки, а для пачки — из списка.
  • Без объекта — в разделе LLM — только в помощнике раздела LLM. В карточках такое действие не показывается: о документе оно ничего не знает и ничего в него не запишет.
  • В списке, через адаптер — только когда помощника открывает код конфигурации с типом «Список». Команда обработки БСП открывает помощника с типом «В карточке объекта», и такие действия там не видны.

Объект выбирается из объектов конфигурации, а не набирается: опечатка спрятала бы действие. Пустое значение или «*» — любой объект: действие появится в карточке каждого документа и справочника. Там же — подпись в помощнике, описание для пользователя, порядок в списке действий и разрешение запускать действие для нескольких выбранных объектов (пачкой, по операции на объект).

Что делает

  • Сценарий — агент, модель и схема ответа; карта извлечения — какие поля вернет модель и куда они лягут.
  • Сначала диалог с моделью — разговор перед результатом.
  • Запрос к модели — что сделать. Схему ответа добавлять в запрос не нужно: она уходит отдельно. В режиме «Сначала диалог» это задание разговора; правка запроса в самом помощнике на разговор не влияет.
  • Подпись кнопки действия — пусто означает подпись по виду действия. При выборе «Только показать» подпись очищается: кнопки у такого действия нет.

Вкладки

  • Вопросы пользователю — что спросить перед запуском. В таблице — «Вопрос (название)» (с ним ответ уходит модели), «Как отвечать», «Обязательно» и «Файл уходит модели». Ниже — откуда брать варианты для выбранного вопроса: «Текст для пользователя», источник, связь с объектом, отбор. Кнопка «Добавить выбор файла» сама узнает, где конфигурация хранит файлы объекта: в БСП 3 — присоединенные файлы, в Документообороте — справочник «Файлы» с версиями; повторное нажатие добавит второй такой вопрос. Отбор по расширению («txt, pdf») задает и порядок автовыбора в пачке.
  • Данные объекта для модели — какие реквизиты и табличные части отдать модели текстом; «*» — все. Строки передаются с номерами, поэтому модель может обновить существующие строки.
  • Условия показа — показывать действие, только если реквизит объекта равен значению, не равен, заполнен или не заполнен. Реквизит набирается вручную: опечатка молча скроет действие.
  • Параметры действия — значения для обработки: она получает их как Параметры.Дополнительные, приведенными к указанным типам. Имя параметра — буквы, цифры и подчеркивание, без пробелов и не с цифры: иначе обработка не вызовется, и действие пропадет из списка.
  • Кому показывать — см. ниже.

Кому показывать

Кто вообще может работать с моделью, задает агент. Эта вкладка сужает круг для одного действия: одно — всем, кто работает с договорами, другое — только администраторам.

УсловиеИмяВыполнено, если
Рольимя роли конфигурации, например ПолныеПравароль назначена пользователю
Группа доступанаименование группы доступа или профиляпользователь входит в группу или у него есть этот профиль

Условий несколько — достаточно любого. Пустая таблица — действие видно всем, у кого есть доступ к агенту. Имя выбирается кнопкой «…»: роли — из конфигурации, группы и профили — из данных базы.

  • В конфигурациях на БСП группа доступа проверяется по составу группы: пользователь в ней сам или через группу пользователей.
  • В Документообороте группы доступа БСП не используются, а профиль выдается полномочиями — пользователю, его рабочей группе или подразделению. Условие «Пользователи» выполнится у всех, кому профиль «Пользователи» выдан, например, через рабочую группу «Все пользователи».

Условие проверяется везде, где действие можно запустить: в списке действий, перед разговором, перед выполнением и в цепочке действий. Скрытое действие не выполнить и в обход списка. Это видимость, а не права на данные: запись в объект по-прежнему идет под правами пользователя.

Обработка и этапы

В ход действия может вмешиваться код — при любом виде действия, а не только у внешнего обработчика. Укажите «Внешняя обработка»: обработку из «Дополнительных отчетов и обработок» или обработку самой конфигурации — Обработка.<Имя>. Затем выберите методы этапов: список дает сама обработка.

ПолеКогда вызываетсяЧто может обработка
Метод проверкипри выборе действия, перед шагом и перед действиемскрыть действие, остановить с причиной, запретить выполнение
Перед запросом к моделифайлы и данные собраны, модель еще не вызванаподать свой файл, дописать данные и запрос, отказать
После ответа моделиответ получен, пользователь его еще не виделпоправить значения, предупредить, отклонить ответ
После действиядействие выполненоприложить файл к созданному объекту, запустить процесс, предложить следующее действие
Метод действиявместо встроенного действия — только у вида «Внешний обработчик»выполнить свое действие, в том числе в несколько шагов с вопросами пользователю

На каждом этапе сначала вызываются процедуры конфигурации из общего модуля AI_ДействияПереопределяемый, потом метод обработки: запрет, объявленный конфигурацией, внешней настройкой не снимается.

Если обработка упала: упавшая проверка — это отказ; подготовка запроса — запуска нет; после ответа — ответ отклоняется; после действия — действие остается выполненным, а пользователь получает сообщение. Причина пишется в журнал регистрации.

Пример. Демо-обработка «AI-действие: демонстрация» содержит метод ПодатьФайлОбъекта. Укажите его в поле «Перед запросом к модели»: обработка сама найдет присоединенный файл объекта и подаст его модели, и вопрос «какой файл» не нужен. Расширения файлов задает параметр действия РасширенияФайлов, например «txt, pdf». Файлы, которые лежат в томах на диске, обработка в безопасном режиме не прочитает — такую обработку регистрируют без безопасного режима.

Перенос и описание

  • Действие переносится в другую базу пакетом — см. AI-помощник, раздел «Пакеты».
  • Описание всех настроенных действий собирается командой «Сохранить инструкцию (HTML)» в AI-помощнике.
