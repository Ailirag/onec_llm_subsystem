# Уточнения правил разработки под эту конфигурацию

Каталог принадлежит проекту. Комплект процесса создаёт его один раз и в замок
`.1c-workflow.lock.json` не включает: файлы здесь правятся свободно, и шаг gate
`process-files-unmodified` на них не смотрит.

Базовые правила — в [..](..). Их правка по месту запрещена и падает на gate.

## Когда писать уточнение

Когда общее правило на этой конфигурации даёт неверный результат или недостаточно
конкретно:

- значение, которого в нейтральном комплекте быть не может: префикс новых
  объектов, название компании в синонимах, канонический порядок блокировок
  регистров, перечень ПДн для журнала регистрации;
- особенность типовой конфигурации, на которой работает проект;
- решение команды, сознательно отличающееся от общего правила.

Когда **не** писать: если правило верно и здесь. Копия базового текста «чтобы
было рядом» разойдётся с оригиналом и станет источником противоречий.

## Формат

Имя файла связывает уточнение с базовым правилом: `queries.md` уточняет
`../queries.md`. Файл без одноимённого базового — дополнительное правило проекта.

Каждый файл начинается с заголовка:

```markdown
---
Уточняет: queries.md
Причина: на типовой БСП этой конфигурации префикс ВТ_ уже занят
---

## Временные таблицы

Префикс временных таблиц — `ВТ_Проект_`.
**Отменяет базовое правило** «Временные таблицы — префикс `ВТ_`».
```

- `Уточняет:` — имя существующего файла базовых правил либо `-` для правила, у
  которого базового аналога нет.
- `Причина:` — одна строка: почему общего правила не хватило. Через полгода
  именно она отвечает на вопрос, можно ли уточнение убрать.

Формат проверяет шаг gate `rules-overlay-valid`: заголовок обязателен, `Уточняет:`
обязан указывать на существующий базовый файл или на `-`, `Причина:` не может
быть пустой. Без проверки overlay через год превращается в набор файлов, про
которые никто не помнит, что они переопределяют.

## Добавление и отмена

По умолчанию уточнение **добавляется** к базовому правилу. Чтобы базовое правило
перестало действовать, внутри уточнения нужна явная пометка:

```
**Отменяет базовое правило** «<точная формулировка из базового файла>».
```

Формулировка приводится дословно — иначе при следующем обновлении комплекта никто
не поймёт, отменено ли ещё существующее правило или уже другое.

## Обратный путь: подъём уточнения в комплект

Если уточнение оказалось не особенностью этой конфигурации, а общим правилом,
верным для любого проекта, — его место в комплекте, а не здесь.

1. Внести правило в `onec-ai-dev-flow`, в `assets/template/docs/rules/`.
2. Поднять версию комплекта, переустановить его в этот проект.
3. Удалить файл уточнения отсюда.

Копирование файла из этого каталога в репозиторий комплекта — не тот путь:
переносится решение, что правило универсально, а не текст. Каталог, который
только растёт, означает, что этот шаг не делают.
