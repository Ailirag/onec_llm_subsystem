# Сценарии пользовательских инструкций

Здесь лежат сценарии этапа `tools\Build-UserGuide.ps1` — он прокликивает их в
веб-клиенте живой базы, снимает каждый шаг, дорисовывает стрелку с курсором мыши
и передаёт артефакт настроенному оформителю. Встроенный оформитель собирает один
самодостаточный HTML.

Это **не тесты**. Регрессия Web UI собирает файлы `*.test.mjs`, и сценарии сюда
не попадают: инструкция обращается к внешним сервисам, зависит от данных стенда
и занимает минуты. Запускают её осознанно, а не каждой фазой.

## Запуск

```powershell
.\tools\Build-UserGuide.ps1 -Scenario <имя файла без расширения>
```

Адрес берётся у стенда Web UI текущей ветки. Стенд должен быть опубликован:

```powershell
.\tools\Publish-WebTestStand.ps1
```

Результат встроенного оформителя — `<userGuides.outputDir>\<сценарий>\index.html`.
Узкий кадр не публикуется: минимальную ширину задаёт
`userGuides.screenshot.minWidth` (по умолчанию 1280). Явный локальный `-Url`
должен совпадать с зарегистрированной публикацией текущей ветки; внешний адрес
можно передать явно без этой привязки.

## Как писать сценарий

Сценарий исполняется как тело `async`-функции: импортов нет, функции раннера
web-test (`navigateLink`, `clickElement`, `fillFields`, `getFormState`, `wait`,
`getPage`, …) доступны глобально. Механику инструкции даёт `guide-runtime.mjs`,
который подставляется перед текстом сценария:

- `step(caption, target, note)` — снять шаг. `target` подсвечивается и получает
  стрелку с курсором; без него шаг снимается как есть. Подсветка находит поля,
  кнопки, команды и разделы, но не заголовки закладок формы;
- `saveGuide(title)` — собрать файл. Вызывается один раз в конце.

Помощники — то, что каждый сценарий иначе пишет сам:

- `openLink(link, titlePart)` — переход по навигационной ссылке с проверкой, что
  открылась форма с `titlePart` в заголовке; повторяет переход, если его
  перекрыла стартовая форма, и сам жмёт «Перейти» в окне «Переход по ссылке»;
- `waitForForm(titlePart, seconds)` — дождаться формы. Нужна сразу после входа:
  стартовые формы конфигурации открываются не мгновенно и перекрывают переход,
  начатый раньше них;
- `openRow(text, keyColumn)` — открыть строку списка по тексту, заданному сидом
  (дата, комментарий). Номера документов на стенде раздаёт нумератор;
- `plainText(value)` — текст для сравнения: 1С разделяет разряды неразрывным
  пробелом, и «3 000,00» из таблицы не равно тем же цифрам в сценарии;
- `checkData(condition, message)` — остановить сборку, если данные стенда не те.

```js
await waitForForm('Начальная страница');
await openLink('Справочник.Контрагенты', 'Контрагенты');
await step(
  'Откройте список контрагентов',
  null,
  'Команда живёт в карточке, поэтому начинаем со списка.');

await clickElement('Создать');
await step(
  'Нажмите «Создать»',
  'Создать',
  'Заполнять карточку руками не придётся: дальше это сделает помощник.');

saveGuide('Создание контрагента');
```

Что оправдало себя на практике:

- **`note` объясняет «зачем», а не повторяет «что»**. Что нажать, видно на
  снимке. Ценно то, чего на снимке нет: почему шаг нужен, что система сделает
  сама, где решение остаётся за человеком;
- **необязательные шаги — в `try/catch`**. Всплывающие подсказки конфигурации
  появляются не всегда, и инструкция не должна из-за них падать;
- **ожидание длинных операций — цикл по `getFormState()`**, а не фиксированная
  пауза: система отвечает по-разному, а инструкция обязана собираться одинаково;
- **данные проверяются до снимка** (`checkData`): число строк списка, порядок и
  суммы результата. Без проверки инструкция соберётся и на неверных данных —
  снимки будут, а показывать они будут не то, что написано в шагах;
- **форма закрывается после просмотра** (`closeForm`), если сценарий вернётся к
  ней после изменения данных: переход к открытой форме её только активирует, и
  снимок покажет прежнее состояние;
- **составное поле заполняется вставкой**: курсор в поле, выделить всё,
  `pasteText`. Выбор типа раннер ведёт через форму выбора, которой у строки нет,
  а `insertText` не помечает форму изменённой, и запись её молча не сохраняет;
- **сообщения, видимые на снимке, объясняются в `note`**: читатель не должен
  гадать, ошибка это или норма;
- **режим раннера `start` не возвращает управление** — при исследовании формы
  его запускают в фоне и шлют шаги через `exec`.

## Под каким пользователем

Стенд публикуется под администратором стенда (`Администратор` без пароля, см.
раздел «Администратор стенда» в `docs/1c-development-workflow.md`). Если инструкция
показывает работу рядового пользователя или отказ по правам, заведите его в сиде и
опубликуйте стенд под ним отдельно: снимок под администратором покажет всё, что
разрешено администратору, и про роль ничего не скажет.

## Паспорт сценария

Чтобы сценарий попадал в цикл инструкций по релизу
(`scripts\workflow\Invoke-ReleaseGuides.ps1`), рядом с `<имя>.mjs` кладётся
`<имя>.guide.json`:

```json
{
  "schemaVersion": 1,
  "tasks": ["<ключ задачи>"],
  "title": "Как …",
  "persona": "<пользователь ИБ, под которым снимать>",
  "seeds": ["<сид>", "…"],
  "help": ["Catalog.Товары", "Report.Продажи"],
  "status": "draft",
  "purpose": "<если проект объявил раздел purpose в userGuides.templateFields>"
}
```

Разделы, которых в прогоне нет — назначение, роли, предусловия, ожидаемый
результат, — живут ЗДЕСЬ, а не в собранном документе. Состав объявляет проект в
`userGuides.templateFields`, имя ключа паспорта совпадает с именем раздела.
Причина простая: документ пересобирается при каждом запуске этапа, и дописанное
прямо в него теряется молча на второй пересборке. Паспорт лежит рядом со
сценарием, едет в MR и виден на ревью. Объявленный и незаполненный раздел роняет
сборку — документ с пустыми заголовками выглядит оформленным и ничего не
сообщает.

- `tasks` — к каким задачам относится инструкция. Обязательно: без него цикл
  не знает, в какой релиз сценарий входит;
- `persona` — необязательно. Сценарий с персоной собирается только на
  публикации этой персоны (`-PersonaUrl`): инструкция про работу рядового
  пользователя или отказ по правам под администратором снята неверно;
- `help` — необязательно. Объекты, о которых этот сценарий: проход инструкций
  проверит, что у них есть встроенная справка по F1. Сценарий только что прошёл
  по этим формам на живом стенде, и отсутствие страницы видно ровно сейчас;
  отдельная проверка выполнялась бы реже и позже. Справка и инструкция
  устаревают вместе, поэтому и проверяются одним проходом;
- `seeds` — необязательно. Данные, которые сценарий ожидает на стенде; цикл
  заливает их адаптером `releaseGuides.seedScript` перед сборкой. Черновик сида
  проверяется `Invoke-ReleaseGuides.ps1 -ProbeSeeds` — с откатом. Общее для
  любой конфигурации (предопределённые данные, первые диалоги БСП, регламентные
  задания) комплект делает сам — базовой подготовкой стенда; что сиду
  предусмотреть заранее, — «Стенд и сиды» в `docs/1c-development-workflow.md`;
- `status` — `draft` (по умолчанию) или `reviewed`. «Проверено человеком»
  ставится только явно: черновик, собранный без ошибок, остаётся черновиком.

Без паспорта сценарий по-прежнему собирается этапом напрямую — он просто не
участвует в цикле релиза.

## Ограничения

Снимки делаются с реальных данных стенда: всё, что видно на экране, попадёт в
файл. Собирайте инструкции на демонстрационных данных и не публикуйте результат
прогона по копии рабочей базы.
