# Модуль формы

**Когда читать:** при правке логики модуля формы и при добавлении обработчиков
событий. Вход — [forms.md](forms.md).

Директивы компиляции и обращения клиент-сервер принадлежат

## Обработчик существует только когда подключён в XML

Процедура-обработчик в модуле формы **ничего не делает**, пока событие не
подключено в XML формы. Это самая частая причина «код добавлен, а ничего не
происходит».

В XML подключение выглядит так:

```xml
<Events>
	<Event name="OnOpen">ПриОткрытии</Event>
	<Event name="BeforeWrite">ПередЗаписью</Event>
	<Event name="OnCreateAtServer">ПриСозданииНаСервере</Event>
</Events>
```

Значение внутри тега — имя процедуры в модуле формы.

Частые события формы и принятые имена обработчиков — **неполный перечень**,
платформа предоставляет десятки событий формы, элементов и таблиц:

| Событие в XML | Имя обработчика | Где исполняется |
|---|---|---|
| `OnOpen` | `ПриОткрытии` | клиент, при открытии формы |
| `OnClose` | `ПриЗакрытии` | клиент, при закрытии |
| `BeforeWrite` | `ПередЗаписью` | клиент, до записи |
| `AfterWrite` | `ПослеЗаписи` | клиент, после записи |
| `OnCreateAtServer` | `ПриСозданииНаСервере` | сервер, создание формы |
| `BeforeWriteAtServer` | `ПередЗаписьюНаСервере` | сервер, до записи объекта |
| `OnWriteAtServer` | `ПриЗаписиНаСервере` | сервер, внутри транзакции записи |
| `AfterWriteAtServer` | `ПослеЗаписиНаСервере` | сервер, после записи |
| `OnReadAtServer` | `ПриЧтенииНаСервере` | сервер, при чтении объекта |

Не путать клиентское событие формы `ПослеЗаписи` с событием модуля объекта
`ПриЗаписи`: это разные события в разных модулях, и обработчик, размещённый не в
том модуле, не вызывается вовсе.

Полный перечень событий брать из синтакс-помощника или из существующей похожей
формы, а не из таблицы выше.

## Зарезервированные имена

Локальные переменные в модуле формы **нельзя** называть именами стандартных
свойств элементов формы:

- `ПараметрыВыбора`
- `СвязиПараметровВыбора`
- `СписокВыбора`
- `ПараметрыОтбора`
- `ОтборСтрок`

Перечень основан на практике и может быть неполным. При подозрении на конфликт —
проверять в Конфигураторе.

**Почему.** В серверном контексте модуля формы платформа может понять
`ПараметрыВыбора = ...` как попытку установить свойство элемента формы, а не как
присваивание локальной переменной. Если тип значения не совпадает с ожидаемым,
возникает ошибка несоответствия типов — в месте, которое выглядит корректным.

Называть конкретно и по контексту:

```bsl
// Плохо
ПараметрыВыбора = Новый Массив;

// Хорошо
ПараметрыВыбораНоменклатуры = Новый Массив;
```

## Данные формы

- Преобразование между данными формы и объектами — `ДанныеФормыВЗначение()` и
  `ЗначениеВДанныеФормы()`.
- Реквизиты формы — не то же, что реквизиты объекта: это представление объекта на
  форме. Правка реквизита формы без записи объекта в базу не попадает.
- Доступность метода, реквизита и элемента проверять в контексте той директивы, из
  которой к ним обращаются: `&НаКлиенте`, `&НаСервере`,
  `&НаСервереБезКонтекста`, `&НаКлиентеНаСервереБезКонтекста`.

## Асинхронность

Обработчики событий формы **не делать** `Асинх`: параметр `Отказ` и влияние на
поток исполнения формы будут проигнорированы. Разбор и рабочие шаблоны —
[async.md](async.md).
