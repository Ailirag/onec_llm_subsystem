Настройки подсистемы LLM

Общие настройки подсистемы: очередь запросов к моделям, сроки хранения, векторизация и связь с конфигурацией. Открываются в разделе LLM → «Сервис» → «Настройки подсистемы LLM». Провайдеры, модели, агенты и действия настраиваются в своих справочниках — см. обзор подсистемы.

Сроки хранения

Через сколько дней регламентное задание очищает старые данные; 0 — не очищать.

  • Тексты прикладных операций — запросы, контекст и ответы операций. Сами операции и их статусы остаются в мониторе.
  • Диалоги — история бесед.
  • Журнал запросов — тексты запросов к моделям, если журнал включен.
  • Тексты оценок результатов — комментарии и исправленные ответы оценок. Сами вердикты остаются.

Векторизация (RAG)

Потоков векторизации — сколько коллекций векторизуется одновременно: каждая коллекция — одно фоновое задание. 0 — одна. См. RAG-коллекции.

Адаптер конфигурации

Что это и когда нужен

Когда модель возвращает значение ссылкой, подсистема находит его в базе по тексту: «Петров Иван Сергеевич» — в пользователях, «Смешанно» — в значениях перечисления. Так работает любой справочник с наименованием и любое перечисление.

Некоторые значения по тексту не найти — для этого нужно знать конфигурацию. В Документообороте исполнитель шаблона процесса бывает не только пользователем:

  • полной ролью — роль исполнителя вместе с объектами адресации: «Юрист», «Руководитель, Юридический отдел». Наименования у такого элемента нет, а нужное сочетание заводится по требованию;
  • автоподстановкой — строкой вроде «Автор процесса», которую Документооборот при старте процесса заменит пользователем.

Адаптер конфигурации — внешняя обработка, которая такие значения знает. Она перечисляет их модели с пояснениями («Юрист — роль; исполняет Петров И. С.») и находит по тексту ответа. Адаптер один на базу: он описывает конфигурацию, а не отдельное действие.

Без адаптера остальное работает как обычно. Он нужен, только если модель должна выбирать такие значения — например, в действии «Собрать маршрут согласования».

Как подключить адаптер Документооборота

  1. Нажмите «Сохранить адаптер Документооборота в файл» — сохранится файл AI_АдаптерДокументооборота.epf. Адаптер поставляется внутри подсистемы, собирать его не нужно. Ссылка видна только в Документообороте.
  2. Зарегистрируйте файл в дополнительных обработках: «Настройка и администрирование» → «Печатные формы, отчеты и обработки» → «Дополнительные отчеты и обработки» → «Добавить из файла…». Подтвердите предупреждение безопасности и нажмите «Записать и закрыть». Размещение в разделах и назначение объектам не нужны: адаптер вызывает сама подсистема.
  3. Вернитесь сюда и в поле «Адаптер конфигурации» нажмите «…». В списке — только адаптеры, с типами значений, которые они знают: «AI-адаптер Документооборота — Полные роли». Выберите его и нажмите «Записать».
  4. В карте извлечения, в поле, где модель выбирает исполнителя, укажите в «Тип ссылки» и пользователей, и полные роли: Справочник.Пользователи, Справочник.ПолныеРоли. Мастер «Новое AI-действие» с заданным адаптером предлагает такой тип сам. Запишите карту — схема ответа перенесется в сценарий.
  5. Проверьте в AI-помощнике: на фразу «сначала юрист, потом главный бухгалтер» модель ответит ролями с исполнителями, а в листе согласования окажутся полные роли.

Что умеет адаптер Документооборота

  • Предлагает модели роли, у которых есть исполнители, — с именами исполнителей. Роли без объектов адресации предлагает, даже если исполнителей еще нет, с пометкой «исполнителей пока нет».
  • Предлагает автоподстановки — только там, где реквизит допускает строку. Исполнитель шаблона ее допускает.
  • Находит «Юрист» и «Руководитель, Юридический отдел» по представлению полной роли. Недостающее сочетание заводит сам, а объект адресации ищет только среди типов, которые допускает роль.
  • Работает в безопасном режиме. Новое сочетание роли и объекта адресации он заведет, если у пользователя есть право на полные роли; уже заведенные находит всегда.

Если адаптер не работает

  • Недоступный адаптер не ломает работу: подсистема ищет значения как без него, а причину пишет в журнал регистрации — событие AI.ПрименениеРекомендаций. Причина, по которой не прочитались автоподстановки, — событие AI.АдаптерДокументооборота.
  • Если в списке выбора пусто, обработка не зарегистрирована, отключена или помечена на удаление. Обработчики действий в списке не показываются: адаптером они не являются.
  • Обработку самой конфигурации указывают вручную: Обработка.<Имя>.

Адаптер для другой конфигурации

Адаптер — обработка с тремя экспортными методами:

МетодЧто делает
ОбрабатываемыеТипы()Возвращает массив полных имен типов, которые адаптер берет на себя, например «Справочник.ПолныеРоли».
ЗначенияДляВыбора(Параметры)Заполняет Параметры.Значения структурами «Представление, Пояснение» — что предложить модели.
НайтиЗначение(Параметры)По Параметры.Текст заполняет Значение, Найдено и Комментарий.

Оба метода получают и само поле: ПолноеИмяОбъекта, ТабличнаяЧасть, ПутьРеквизита, ТипыСсылки. Готовый пример — исходники адаптера Документооборота в поставке подсистемы.

Обработка помощника для БСП

«Сохранить обработку помощника для БСП в файл» сохраняет внешнюю обработку «AI-помощник: сценарии для объекта». Зарегистрированная в «Дополнительных отчетах и обработках», она добавляет команду «AI-помощник» в подменю «Заполнить» карточек и списков тех объектов, для которых настроены действия. Назначение объектам подставляется само, а для объекта, добавленного позже, — кнопкой «Подключить команду к объекту» в месте запуска.
