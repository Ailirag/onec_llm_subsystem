# Подсистема LLM для 1С

Подсистема для подключения языковых моделей к конфигурациям
1С:Предприятия. Проект поставляется как расширение и как набор объектов,
который можно встроить в основную конфигурацию.

> Проект находится в активной разработке. Перед установкой в рабочую базу
> проверьте релиз на копии информационной базы и настройте минимально
> необходимые роли и профили доступа.

## Возможности

- OpenAI-совместимые API, Yandex AI, Z.AI, Ollama и LM Studio.
- Загрузка доступных моделей провайдера с выбором нужных моделей.
- Обычный и агентский режимы диалога.
- Асинхронная обработка сообщений и сохраняемая история бесед.
- Вложения и предварительный анализ поддерживаемых форматов мультимодальной
  моделью.
- RAG и интеграция с векторным хранилищем.
- Исследование метаданных и чтение данных через ограниченные инструменты агента.
- Профили доступа к данным, назначение агентов пользователям и группам.
- Подключение удалённых MCP-серверов по HTTP с явным списком разрешённых
  инструментов.
- Журналирование запросов, шагов агента и расхода токенов.

Полное описание назначения, возможностей и текущих ограничений приведено в
[обзоре решения](docs/solution-overview.md). Общий поток вызовов описан в
[архитектуре подсистемы](docs/architecture.md).

## Варианты поставки

| Вариант | Назначение |
| --- | --- |
| `cfe llm` | Канонические XML-исходники расширения |
| `cf llm` | Генерируемая конфигурация-донор для встраивания |
| `LLM_isolated*.cfe` | Скомпилированное расширение из GitHub Releases |
| `LLM_Subsystem.cf` | Скомпилированная конфигурация-донор из GitHub Releases |

Каталог `cf llm` и бинарные файлы являются результатами сборки и в Git не
хранятся.

Бинарный релиз должен публиковаться архивом вместе с `LICENSE` и `NOTICE`, а не
отдельным файлом `.cf` или `.cfe`.

## Совместимость

- режим совместимости расширения: 1С:Предприятие 8.3.17;
- управляемое приложение;
- файловый или клиент-серверный вариант работы;
- для внешних моделей сервер 1С должен иметь сетевой доступ к API провайдера.

Совместимость с конкретной прикладной конфигурацией зависит от её режима
совместимости, состава ролей и ограничений расширений. Проверяйте установку
на копии целевой базы.

## Быстрый старт

1. Соберите расширение из `cfe llm` или возьмите `.cfe` из раздела Releases.
2. Подключите расширение к тестовой базе и обновите конфигурацию базы данных.
3. Назначьте администратору роли подсистемы. Не выдавайте роль
   `AI_ПолныеПрава` обычным пользователям.
4. Создайте провайдера, укажите адрес API и сохраните ключ в информационной
   базе.
5. Загрузите и отметьте необходимые модели.
6. Создайте агента, профиль доступа к данным и назначения пользователей.
7. Выполните тестовый запрос к модели до включения агента для пользователей.

API-ключи, MCP-секреты, адреса корпоративных сервисов и параметры конкретной
информационной базы не должны храниться в Git.

## Агентский доступ к данным

Агент получает сведения о метаданных и выполняет запросы только через
инструменты подсистемы. Доступ ограничивается одновременно:

- ролями и RLS текущего пользователя 1С;
- профилем доступа агента;
- перечнем разрешённых объектов и полей;
- административными лимитами профиля;
- проверкой запросов перед выполнением.

Подробности: [Анализ данных агентом](docs/agent-data-analysis.md).

Предоставление агенту доступа к данным означает, что выбранные сведения могут
быть отправлены внешнему провайдеру модели. Учитывайте требования организации
к персональным данным, коммерческой тайне и трансграничной передаче.

## MCP

В текущей архитектуре поддерживаются удалённые MCP-серверы с HTTP-транспортом.
Каждое подключение и разрешённые инструменты задаются в профиле MCP. Не
подключайте непроверенные серверы: инструмент MCP выполняется вне границ
информационной базы и может иметь собственные полномочия.

## Встраивание в конфигурацию

Проверка состава и генерация конфигурации-донора:

```powershell
.\tools\Test-SubsystemCoverage.ps1
.\tools\Build-EmbeddedConfiguration.ps1
```

Слияние с XML-выгрузкой целевой конфигурации:

```powershell
.\tools\Merge-EmbeddedConfiguration.ps1 `
    -TargetConfigurationPath "C:\project\src" `
    -OutputDirectory ".build\merged-cf"
```

Подробности: [Встраивание подсистемы](docs/embedded-subsystem.md).

## Проверка изменений

Перед pull request выполните:

```powershell
.\tools\Test-PublicationReadiness.ps1
.\tools\Test-SubsystemCoverage.ps1
```

Затем загрузите XML-исходники в тестовую базу, обновите конфигурацию и
проведите дымовой тест:

1. открытие форм провайдера, модели, агента и профиля доступа;
2. успешный ответ модели;
3. обычный диалог и восстановление истории;
4. агентский вызов инструментов;
5. загрузка вложения;
6. очистка тестовых данных.

## Структура

- `cfe llm` — исходники расширения;
- `cf` — минимальный шаблон для генерации конфигурации-донора;
- `docs` — архитектура, внедрение и эксплуатация;
- `manifest` — декларация состава подсистемы;
- `tools` — проверки, генерация и слияние XML.
