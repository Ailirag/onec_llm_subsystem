# Расширения конфигурации

**Когда читать:** при написании и ревью кода расширения.

Приоритет способа доработки и правила размещения новых объектов —
[change-markers.md](change-markers.md) и [architecture.md](architecture.md). Здесь —
практика: типы перехватчиков, семантика `ПродолжитьВызов`, маркеры, ограничения
заимствованных объектов.

Расширения проекта, их порядок загрузки и обязательность объявлены в
`.1c-workflow.json`. Загружать расширения всегда полностью в порядке `loadOrder` и
после загрузки проверять применимость — это правило процесса, оно в блоке
`AGENTS.md`.

## Псевдоним расширения

Имена процедур и функций, которые расширение вводит, начинаются с **собственного
короткого псевдонима расширения** — он задаётся в свойствах расширения. Это не то
же, что префикс новых объектов метаданных: префикс относится к объектам и
реквизитам, псевдоним — к именам методов, и он предотвращает конфликт имён между
расширениями.

Одно расширение может и добавить реквизит `<Префикс>Признак` типовому объекту, и
определить перехватчик `Расш_ПриЗаписи` в том же модуле.

Псевдоним не должен содержать буквы «ё» — см. типографику в
[code-style.md](code-style.md).

## Типы перехватчиков

| Директива | Когда применять |
|---|---|
| `&Перед("ИмяМетода")` | код до исходного метода |
| `&После("ИмяМетода")` | код после исходного метода |
| `&Вместо("ИмяМетода")` | полная замена метода; исходный вызывается через `ПродолжитьВызов()` |
| `&ИзменениеИКонтроль("ИмяМетода")` | контролируемая правка **копии** тела исходного метода маркерами `#Вставка` / `#Удаление` |

Предпочтение `&Перед` и `&После`. `&Вместо` и `&ИзменениеИКонтроль` — только когда
до и после результата не дают. На один метод во всех расширениях может
подействовать не более одного `&ИзменениеИКонтроль` либо конкурирующего `&Вместо`;
второе расширение просто не применится, и об этом узнают при обновлении.

### Перед и После

```bsl
&НаСервере
&Перед("ПриЗаписи")
Процедура Расш_ПриЗаписи()
	// исполняется ДО исходного ПриЗаписи
КонецПроцедуры

&НаСервере
&После("ПриЗаписи")
Процедура Расш_ПослеЗаписи()
	// исполняется ПОСЛЕ исходного ПриЗаписи
КонецПроцедуры
```

### Вместо

```bsl
&НаСервере
&Вместо("ОбработкаПроведения")
Процедура Расш_ОбработкаПроведения(Отказ, РежимПроведения)

	// код до исходного

	ПродолжитьВызов(Отказ, РежимПроведения);

	// код после исходного, в том же контексте

КонецПроцедуры
```

Для функции результат нужно принять и вернуть:

```bsl
&Вместо("Цена")
Функция Расш_Цена(Номенклатура)

	Результат = ПродолжитьВызов(Номенклатура);
	// при необходимости скорректировать Результат
	Возврат Результат;

КонецФункции
```

### ИзменениеИКонтроль

Тело перехватчика — **копия исходного метода**. Каждое собственное изменение
обязано быть помечено; непомеченные строки обязаны совпадать с оригиналом
поставщика дословно — в этом и состоит «контроль». `ПродолжитьВызов()` здесь
**не используется**: изменённое тело и есть то, что исполняется вместо исходного.

```bsl
&НаСервере
&ИзменениеИКонтроль("ОбработкаЗаполнения")
Процедура Расш_ОбработкаЗаполнения(ДанныеЗаполнения, СтандартнаяОбработка)

	// ... непомеченные строки оригинала ...

#Удаление
	// удаляемые строки оригинала остаются между маркерами для контроля
#КонецУдаления
#Вставка
	// новый код
#КонецВставки

	// ... дальше непомеченные строки оригинала ...

КонецПроцедуры
```

Маркеры ставить каждый **на отдельной строке без отступа**. Они сохраняют
осмысленность сравнения при обновлении базовой конфигурации: без них
пересинхронизация расширения превращается в чтение двух похожих тел метода целиком.

## Правила ПродолжитьВызов

| Директива | `ПродолжитьВызов()` |
|---|---|
| `&Перед` | **не вызывать**: исходный метод исполнится сам, после |
| `&После` | **не вызывать**: исходный метод уже исполнен |
| `&Вместо` | **вызывать**, если исходный метод должен исполниться. Аргументы те же; для функции использовать возвращаемое значение |
| `&ИзменениеИКонтроль` | **не вызывать** |

Забытый `ПродолжитьВызов` в `&Вместо` — самая дорогая ошибка в расширениях:
типовая логика перестаёт исполняться, ошибки нет, отказ проявляется как
неправильные данные.

## Заимствованные объекты

- Заимствованный объект — **не копия**, а ссылка на объект базовой конфигурации,
  введённая в область видимости расширения, чтобы к нему можно было прицепить
  перехватчики и добавить свои реквизиты, табличные части, элементы форм.
  Определение по-прежнему живёт в базовой конфигурации; при её обновлении
  заимствованный объект перечитывается, и расширение применяется поверх.
- **Удалять** существующие реквизиты и табличные части заимствованного объекта
  нельзя: они принадлежат базовой конфигурации.
- **Добавлять** свои реквизиты и табличные части можно, с префиксом проекта.
- Модули заимствованных объектов — только перехватчики, без прямой правки тела
  исходной процедуры.
- Формы заимствованных объектов — элементы добавлять можно, существующие удалять
  нельзя.

## Антипаттерны

### Прямая правка модуля заимствованного объекта

```bsl
// Неправильно: правка исходного кода на месте
Процедура ПриЗаписи()
	// изменённый код
КонецПроцедуры

// Правильно: перехватчик
&Перед("ПриЗаписи")
Процедура Расш_ПриЗаписи()
	// дополнительный код
КонецПроцедуры
```

### ПродолжитьВызов внутри ИзменениеИКонтроль

Директива предполагает контролируемую копию тела; вызов исходного метода означал
бы двойное исполнение.

### Метод расширения без псевдонима

```bsl
// Плохо: конфликт имён с другими расширениями
Процедура ДополнительнаяПроверка()

// Хорошо
Процедура Расш_ДополнительнаяПроверка()
```

## Назначение расширения

Свойство «Назначение» влияет на поведение при обновлении и на то, как платформа
повторно применяет расширение после обновления базовой конфигурации:

| Назначение | Когда |
|---|---|
| Исправление (patch) | минимальные изменения, только перехватчики |
| Адаптация (customization) | реквизиты, формы, модули |
| Дополнение (add-on) | новая функциональность целиком |

Назначение выбирается при создании расширения; смена назначения позже — не
свойство, а переработка.
