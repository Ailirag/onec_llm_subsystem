# Архитектура подсистемы LLM

Документ хранит архитектурные сведения, которые раньше находились в служебных
объектах метаданных `AI_TODO` и `AI_ОписаниеРешения_*`. Исполняемый код не
обращался к этим объектам.

## Обычный запрос к модели

1. `AI_Клиент`, `AI_Песочница` или `AI_ЧатПоДаннымБазы` формирует запрос.
2. `AI_Агенты`, `AI_Модели` и `AI_Провайдеры` определяют настройки вызова.
3. Адаптер провайдера (`OPI_OpenAI`, `OPI_Ollama`, `AI_YandexAI`,
   `AI_LMStudio` или `AI_ZAI`) подготавливает HTTP-запрос.
4. `OPI_ЗапросыHTTP` и `OPI_HTTPКлиент` выполняют обращение к API.
5. Результат записывается в журнал и историю диалога.

Асинхронный вариант помещает запрос в `AI_ОчередьЗапросов`. Регламентное
задание `AI_ОбработкаОчередиЗапросов` вызывает
`AI_ОбработкаСервер.ОбработкаОчереди`.

## Агентский режим

Агентские операции и их шаги хранятся в регистрах
`AI_АгентскиеОперации` и `AI_ШагиАгентскихОпераций`. Инструменты базы
выполняются через `AI_ИнструментыАгента` с проверками
`AI_ПолитикиАгента` и `AI_БезопасныеЗапросы`.

Доступ пользователей к агентам и профилям данных контролируют
`AI_ДоступКАгентамСервер`, `AI_ДоступКАгентамКлиентСервер` и роли подсистемы.

## MCP

Справочники `AI_MCPСерверы`, `AI_MCPИнструменты` и `AI_ПрофилиMCP` описывают
подключения и разрешенные инструменты. Реестр инструментов, HTTP-транспорт и
клиент реализованы модулями `AI_MCPРеестрИнструментов`,
`AI_MCPТранспортHTTP` и `AI_MCPКлиент`. Секреты хранятся отдельно в
`AI_СекретыMCP`.

## RAG

Расширение загружает фрагменты в Qdrant и ищет по ним, но не знает, какие
данные конфигурации индексировать: текст фрагментов собирает проект внедрения.

Загрузка:

1. Проект внедрения ставит прикладные объекты в очередь подготовки
   `AI_ОчередьПодготовкиКВекторизации`: подпиской на запись с обработчиком
   `AI_ОбработкаСервер.AI_RAG_ПередЗаписьюПриЗаписи` или методом
   `ПоставитьСсылкуВОчередь` менеджера регистра.
2. Задание `AI_ОбработкаОчередиПодготовкиКВекторизации` раздает ссылки по
   типам в `AI_RAG.ОбработкаМассиваОчередиПодготовкиПоТипу`. В поставке это
   заглушка: для любого типа она пишет ошибку в журнал регистрации и
   оставляет ссылки в очереди. Сборщик типа пишет проект внедрения: находит
   коллекции типа (`Справочники.AI_RAGКоллекции.ПолучитьКоллекцииПоПредставлениюТипа`),
   делит текст объекта на фрагменты, кладет их в `AI_ОчередьВекторизации`
   методом `ЗаписатьЭлементВекторизации` (структура — `ПолучитьПараметрыЭлемента`)
   и в той же транзакции убирает ссылку из очереди подготовки
   (`УдалитьСсылкуИзОчереди`). Без очереди подготовки можно обойтись и вызывать
   `ЗаписатьЭлементВекторизации` прямо из своей подписки.
3. Задание `AI_ОбработкаОчередиВекторизации` по каждой коллекции создает ее в
   Qdrant, если коллекции нет, и отмечает созданной, получает векторы через
   OpenAI-совместимый `POST /embeddings`, загружает точки и удаляет из Qdrant
   фрагменты, которых больше нет в объекте.
4. `AI_ИдентификаторыЧанков` хранит идентификаторы и хеши отправленных
   фрагментов: неизмененный фрагмент повторно не отправляется. Реестр не
   различает коллекции, поэтому фрагмент, поставленный сразу в несколько
   коллекций, векторизуется только в одну из них.

Поиск: `AI_RAG.ДанныеRAGАгента` собирает отмеченные коллекции агента с
ненулевым лимитом (песочница — `ДанныеRAGПоНастройкам` по строкам формы).
`AI_Клиент` векторизует вопрос, ищет в каждой коллекции с фильтром по меткам
доступа агента и передает найденное модели блоком `--RAG_CONTEXT--`. Таймауты
сервисов берутся из подключения RAG (0 — 30 секунд), повторов нет; ошибка
сервиса прерывает запрос с кодом ответа и сообщением сервиса.

Для коллекции, которую наполняют вне 1С, поиск читает из payload точки поля
`text` (текст для модели), `header`, `subheader`, `nav_ref`, `chunk_num`,
`chunks_total`, а фильтр меток — `permissions`, `tenant`, `org_guid`,
`entity_type`. Флажок «Создана в Qdrant» у такой коллекции ставят вручную.

Конкретные подписки на объекты основной конфигурации создаются в проекте
внедрения сознательно.
