Карты извлечения реквизитов

Карта описывает, какие поля вернет модель и в какие реквизиты объекта они лягут. Из карты строится схема ответа сценария, по ней же ответ раскладывается и применяется. Писать можно только в то, что есть в карте: это белый список реквизитов действия.

Шапка карты

  • Активна — выключенная карта не работает: ответ по ней не разбирается и не применяется, мастер ее не предлагает.
  • Заменять строки табличных частей — строки из ответа заменяют строки объекта, а не дописываются.
  • Обновлять существующие строки по номеру — модель называет номер строки из данных объекта, и значения ложатся в эту строку. Требует, чтобы место запуска передавало модели табличную часть (вкладка «Данные объекта для модели»).

Поля

КолонкаЧто задает
РеквизитНазвание поля для пользователя в таблице результата. Модель видит его только в разговоре; в обычном запуске — ключ и подсказку.
ТипСтрока, число, дата, булево или ссылка.
Реквизит объекта, Табличная частьКуда ложится значение: реквизит шапки или колонка табличной части. Путь через точку не поддерживается.
Доп. реквизит (свойство)Дополнительный реквизит БСП — по наименованию свойства. Значение свойства-списка ищется только среди значений этого свойства.
Тип ссылкиГде искать значение: полные имена через запятую, например Справочник.Пользователи, Справочник.ПолныеРоли. Типы ищутся по очереди.
Искать по наименованиюДля типа «Ссылка»: искать значение в базе по тексту модели. Без флажка значение не распознается и не применится.
Выбирать из существующихСписок существующих значений уходит модели, и она выбирает из него, а не пишет как в документе. Для перечислений — всегда. Длинные списки (больше 100 значений) не передаются: значение ищется по наименованию.
ОбязательноеТолько пометка: если модель не вернет значение, в результате будет комментарий «Обязательное поле не заполнено моделью». Применению это не мешает.
Подсказка моделиПравила предметной области, которых модель знать не может.
Ключ в ответеИмя поля в ответе модели латиницей. Пусто — выведется из реквизита при записи карты.

Значения, которые подсистема по тексту не находит, — например роли исполнителей и автоподстановки Документооборота, — ищет адаптер конфигурации. Их тип указывается в «Тип ссылки» как обычно.

Схема ответа

Схема ответа хранится в сценарии и переносится туда при записи активной карты — во все сценарии мест запуска, где выбрана карта. Над таблицей форма пишет, совпадает ли схема со сценариями. Кнопка «Записать схему в сценарии» нужна, только если схема разошлась (например, сценарий правили вручную); она работает по записанной карте. «Еще» → «Показать схему ответа» — сама схема, ничего не записывает.

Подсказки: как объяснить модели правила

Модель не знает правил вашей конфигурации. Пример из шаблона согласования Документооборота — поле «Порядок согласования»:

Порядок — относительно предыдущей строки: «После предыдущего» — следующий этап, «Вместе с предыдущим» — тот же этап, что у предыдущей строки. Пример: «сначала А, потом одновременно Б и В, затем Г» — А: После предыдущего; Б: После предыдущего; В: Вместе с предыдущим; Г: После предыдущего.

Без примера модель ставила «Вместе с предыдущим» первому из одновременных. Подсказка с примером работает лучше длинного объяснения.
