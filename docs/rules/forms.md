**Когда читать:** первым файлом при любой задаче по управляемой форме. Дальше —
только те файлы, которые выбирает таблица ниже.

## Создание и структурная правка формы

- **XML формы проверять схемой** после любой правки. Форма, которая разбирается в
  редакторе, — не то же самое, что форма, которая загружается в Конфигуратор.
- **Типовые ловушки XML** — [metadata-xml.md](metadata-xml.md). Прочитать до
  правки, а не после отказа загрузки.
- **Ручную правку `Form.xml` в задачной ветке использовать по возможности не
  надо.** Правка через Конфигуратор с переносом выбранных объектов
  (`Import-DesignerChanges.ps1`) сохраняет структуру, которую платформа ожидает:
  порядок `ChildObjects`, уникальность идентификаторов, кодировку. Разбор
  конфликтов по `Form.xml` — в `docs/merge-conflicts.md`.
- **Именование элементов** на типовой форме — с префиксом проекта. Внутри новой
  формы, у которой префикс уже в имени объекта, элементы префикс не повторяют —
  [change-markers.md](change-markers.md).

## Доработка типовых форм

- Все правки типовых форм выполняются **программно**, не визуально. Элементы
  создаются в `ПриСозданииНаСервере`, через подписку или через расширение.
  Визуальная правка типовой формы превращает каждое обновление поставщика в ручное
  слияние `Form.xml`, а это самый неудобный для слияния файл выгрузки.
- Если у формы есть страницы — добавленные элементы уходят на отдельную страницу.
  Если страниц нет — в группу без заголовка.
- Визуальную правку форм **в расширениях** свести к минимуму, изменения вносить
  кодом.

## Новые формы

- Реквизиты шапки и табличные части разносить по страницам: «Основное» — шапка,
  затем по странице на табличную часть.
- Для страниц с табличными частями заполнять свойство пути к данным шапки.
- Ссылочные поля — ширина до 27 символов.
- Многострочные поля комментария — ширина 79, высота 3.

## Проверка заполнения

- Использовать свойство проверки заполнения у реквизитов формы, а не собственные
  проверки в коде: свойство даёт единообразное сообщение, привязанное к полю.
- Перед записью и проведением вызывать `ПроверитьЗаполнение()`:

```bsl
Если Не ПроверитьЗаполнение() Тогда
	Возврат;
КонецЕсли;
```

## Команды формы

Команде, изменяющей данные, устанавливать признак изменения сохраняемых данных.
Без него платформа не предупредит пользователя о несохранённых изменениях, и
данные теряются без сообщения.

## Тесты

Изменение формы, интерфейса или отчёта требует обновления соответствующего теста в
том же MR — это правило процесса, оно в блоке `AGENTS.md`. Проверка, читающая
отрисованное состояние, пишется с ожиданием готовности, а не с расчётом на тайминг.
