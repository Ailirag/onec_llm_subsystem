# Архитектура и платформа

**Когда читать:** когда решается, где разместить код, как разделить
клиент и сервер, как вернуть составной результат, что делать с длительной
операцией, где кеш и где привилегированный режим.

Стиль и запреты уровня выражения — [code-style.md](code-style.md). Каталог
антипаттернов с оценкой тяжести — [anti-patterns.md](anti-patterns.md).

## Размещение кода

- Бизнес-логика — **в общих модулях**, не в модулях форм. Модуль формы отвечает за
  форму, а не за предметную область.
- Имена общих модулей — по суффиксной конвенции БСП:

| Суффикс | Смысл |
|---|---|
| без суффикса | серверный модуль (`РаботаСЗаказами`) |
| `Клиент` | только клиент |
| `КлиентСервер` | компилируется на обеих сторонах |
| `ВызовСервера` | серверный модуль, вызываемый с клиента |
| `Глобальный` | глобальный клиентский модуль |
| `ПовтИсп` | повторное использование возвращаемых значений |
| `Переопределяемый` | точки переопределения для проекта |

- Модули объектов и менеджеров — обязательная директива препроцессора
  `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда`.
  Состав областей — [module-structure.md](module-structure.md).
- Новые объекты метаданных размещать в подсистемах.
- Составной тип, используемый повторно, оформлять `ОпределяемымТипом`.

Куда именно попадают новые объекты — в основную конфигурацию или в расширение —
решает проект. Правило по умолчанию: **в основную конфигурацию**, расширение
используется для перехвата событий и доработки типовой функциональности. Проект,
у которого правило иное, фиксирует это в `docs/rules/project/architecture.md`.

## Приёмы

### Составной результат — структурой

```bsl
Результат = Новый Структура;
Результат.Вставить("ПроверкаПройдена", ПроверкаПройдена);
Результат.Вставить("ТекстОшибки", ТекстОшибки);

Возврат Результат;
```

### Ранний возврат

```bsl
Если Отказ Тогда
	Возврат;
КонецЕсли;

Если Не ЗначениеЗаполнено(ДатаДействия) Тогда
	Возврат ЗначениеПоУмолчанию;
КонецЕсли;
```

Вложенность снижается ранним возвратом, а не дополнительным `Иначе`.

### Защитная проверка типа

В BSL нет строгой типизации. На входе метода, где тип критичен, проверять и
приводить:

```bsl
Если ТипЗнч(ДокументыИлиСсылка) <> Тип("Массив") Тогда
	Документы = Новый Массив;
	Документы.Добавить(ДокументыИлиСсылка);
Иначе
	Документы = ДокументыИлиСсылка;
КонецЕсли;
```

Приведение одиночного значения к массиву — `ОбщегоНазначенияКлиентСервер.ЗначениеВМассиве()`.

### Безопасный доступ к свойству структуры

```bsl
Если ПараметрыОтчета.Свойство("ДатаНачала", ДатаНачала) Тогда
	// ДатаНачала заполнена
КонецЕсли;
```

Обращение `ПараметрыОтчета.ДатаНачала` без проверки падает на первом вызове, в
котором ключ не передан, — и падает у пользователя, а не у автора.

### Поиск строк в таблице значений

```bsl
СтруктураОтбора = Новый Структура("ВидСпецодежды", ТекущаяСтрока.ВидСпецодежды);
НайденныеСтроки = ТаблицаДанных.НайтиСтроки(СтруктураОтбора);

Если НайденныеСтроки.Количество() = 0 Тогда
	Продолжить;
КонецЕсли;
```

### Подписки на события

Подписка предпочтительнее правки типового модуля. Методы подписок держать в
отдельном общем модуле проекта, а не рассыпать по модулям объектов.

### Длительные операции

Операции длиннее примерно 10 секунд выносить в фоновое задание с индикацией
прогресса, интерфейс не блокировать. Шаблон и типовые ошибки —
[platform-cases.md](platform-cases.md).

## Клиент-сервер

- **`&НаСервереБезКонтекста` обязательна** для всех серверных методов, которые не
  обращаются к данным формы. `&НаСервере` допустима только когда метод прямо
  читает или пишет реквизиты либо элементы формы.
- Если методу нужно только значение реквизита формы — передать параметром и
  использовать `&НаСервереБезКонтекста`.
- Несколько серверных вызовов подряд из одного клиентского обработчика собирать в
  один вызов, возвращающий структуру.
- Диалоги на сервере запрещены полностью.

Модальные вызовы (`Вопрос()`, `Предупреждение()`, `ВвестиЧисло()`,
`ВвестиСтроку()`, `ВвестиДату()`, `ВвестиЗначение()`, `ОткрытьЗначение()`)
запрещены. Замена зависит от `platformVersion` из `.1c-workflow.json`: с 8.3.18 —
`Асинх` / `Ждать` ([async.md](async.md)), раньше — `ОписаниеОповещения`.

## Безопасность

- `Выполнить()` и `Вычислить()` — запрещены без крайней необходимости.
- Учётные данные в коде запрещены. Хранить через подсистему безопасного хранилища
  БСП.
- RLS проектировать вместе с требованиями к доступу, а не после —
  [access-rights.md](access-rights.md).

## Обработка ошибок

- Локализация строк — `НСтр("ru = '...'")` с
  `СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку()`.
- Сбор нескольких ошибок — в одну переменную через `Символы.ПС`.
- В журнал писать `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, а не
  `КраткоеПредставлениеОшибки()`: краткое представление теряет стек и причину, и
  разбор дефекта начинается с нуля.
- Пустые обработчики исключений запрещены.

Положительная сторона — когда писать в журнал вообще, какие уровни и как
называть события — [logging.md](logging.md). Читать вместе.

## Производительность

Обязательный минимум. Каталог с оценкой тяжести —
[anti-patterns.md](anti-patterns.md). Блокировки и транзакции —
[locks.md](locks.md). Запросы — [queries.md](queries.md).

- **Массовые операции — на сервере.** Обращения клиент-сервер внутри цикла
  недопустимы.
- **Запросы никогда внутри цикла.** Пакетные запросы с временными таблицами.
- **Привилегированный режим** — `УстановитьПривилегированныйРежим(Истина)` только
  где нужно и всегда в паре с `УстановитьПривилегированныйРежим(Ложь)`. Текущее
  состояние — `ПривилегированныйРежим()`.
- **Кеширование** — повторяемые вычисления кешировать: `Соответствие` в пределах
  вызова, параметры сеанса в пределах сеанса, регистр сведений между сеансами.
- **Коллекции** — массовое заполнение `ЗаполнитьЗначенияСвойств()`. Поиск: до
  сотни элементов достаточно `Найти()` / `НайтиПоЗначению()`; от тысячи или внутри
  цикла — индекс на `Соответствие` либо `ТаблицаЗначений.Индексы.Добавить(...)` +
  `НайтиСтроки()`.
- **Реквизиты через точку** — не читать: разбор в разделе ниже.
- **Транзакции держать короткими**: без взаимодействия с пользователем, без
  длительных операций, без обращений к внешним сервисам.

## Чтение реквизитов по ссылке

Обращение через точку (`Контрагент.ИНН`) читает из базы объект целиком.
`[Правило проекта: строже ИТС]` — ИТС допускает точку в неинтенсивном коде, здесь
это запрещено вне тривиальных обработчиков с одним вызовом.

| Метод | Назначение |
|---|---|
| `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` | один реквизит одной ссылки |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъекта` | несколько реквизитов одной ссылки |
| `ОбщегоНазначения.ЗначениеРеквизитаОбъектов` | один реквизит нескольких ссылок |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъектов` | несколько реквизитов нескольких ссылок |

Повторные обращения кешировать через `Соответствие`. Для набора ссылок — пакетный
метод или запрос с `Ссылка В (&МассивСсылок)`, а не вызов в цикле.

## Запахи кода

| Запах | Признаки | Что делать |
|---|---|---|
| Группа данных | одни и те же 3+ параметра ходят вместе по нескольким методам | собрать структурой через функцию-конструктор |
| Одержимость примитивами | строки вместо перечислений, числовые коды вместо ссылок | `Перечисление`, `СправочникСсылка`, `ОпределяемыйТип` |
| Расходящееся изменение | один модуль правят по разным причинам | разделить по ответственности |
| Стрельба дробью | одно изменение логики требует правок в пяти местах | собрать связанную логику в один общий модуль |
| Зависть к чужим данным | метод модуля формы плотно работает с данными другого объекта | перенести в общий модуль этого объекта |
| Переиспользование переменной | одна переменная хранит разное на разных этапах | отдельная переменная на каждое значение |

Архитектурные запахи, которые дороже всего исправлять позже: «модуль-бог» (сотни
процедур в одном модуле), жёсткая связанность через детали реализации,
copy-paste вместо общего модуля, преждевременная оптимизация.
