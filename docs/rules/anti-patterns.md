# Антипаттерны 1С

**Когда читать:** при ревью, при оптимизации, при разборе медленной работы.

Здесь — **каталог**: признак, тяжесть, шаблон исправления. Сами нормативные
правила принадлежат другим файлам: запросы — [queries.md](queries.md), чтение
реквизитов и клиент-сервер — [architecture.md](architecture.md), блокировки —
[locks.md](locks.md). При расхождении прав тот файл, которому правило
принадлежит; здесь правится пример.

## Критические

### 1. Запрос в цикле

**Последствие:** N обращений к базе вместо одного. **Тяжесть: критическая.**

```bsl
// Плохо: N обращений к базе
Для Каждого Строка Из Данные Цикл
	Запрос = Новый Запрос("ВЫБРАТЬ ... ГДЕ Ссылка = &Ссылка");
	Запрос.УстановитьПараметр("Ссылка", Строка.Ссылка);
	РезультатЗапроса = Запрос.Выполнить();
КонецЦикла;

// Хорошо: одно обращение
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ ...
|ГДЕ
|	Ссылка В (&СписокСсылок)";
Запрос.УстановитьПараметр("СписокСсылок", Данные.ВыгрузитьКолонку("Ссылка"));
РезультатЗапроса = Запрос.Выполнить();
```

### 2. Чтение реквизита через точку

**Последствие:** объект читается из базы целиком на каждый реквизит.
**Тяжесть: критическая.** `[Правило проекта: строже ИТС]`

```bsl
// Плохо: полное чтение объекта на каждый реквизит
ИНН = Контрагент.ИНН;
КПП = Контрагент.КПП;
Наименование = Контрагент.Наименование;

// Хорошо: один адресный запрос
Реквизиты = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
	Контрагент, "ИНН, КПП, Наименование");
ИНН = Реквизиты.ИНН;
КПП = Реквизиты.КПП;
Наименование = Реквизиты.Наименование;
```

### 3. Подзапрос в списке выборки

**Последствие:** подзапрос исполняется для каждой строки. **Тяжесть: критическая.**

```bsl
// Плохо
"ВЫБРАТЬ
|	Заказы.Ссылка,
|	(ВЫБРАТЬ СУММА(Оплаты.Сумма)
|	 ИЗ Документ.Оплата КАК Оплаты
|	 ГДЕ Оплаты.Заказ = Заказы.Ссылка) КАК СуммаОплат
|ИЗ
|	Документ.Заказ КАК Заказы"

// Хорошо: соединение с агрегацией
"ВЫБРАТЬ
|	Заказы.Ссылка КАК Ссылка,
|	ЕСТЬNULL(Оплаты.СуммаОплат, 0) КАК СуммаОплат
|ИЗ
|	Документ.Заказ КАК Заказы
|		ЛЕВОЕ СОЕДИНЕНИЕ (
|			ВЫБРАТЬ
|				Оплаты.Заказ КАК Заказ,
|				СУММА(Оплаты.Сумма) КАК СуммаОплат
|			ИЗ
|				Документ.Оплата КАК Оплаты
|			СГРУППИРОВАТЬ ПО
|				Оплаты.Заказ) КАК Оплаты
|		ПО Заказы.Ссылка = Оплаты.Заказ"
```

### 4. Коррелированный подзапрос в условии

**Последствие:** подзапрос исполняется для каждой строки внешнего источника,
сложность квадратичная. **Тяжесть: критическая.**

```bsl
// Плохо: ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 ...) выполняется на каждой строке
"ВЫБРАТЬ ...
|ИЗ
|	РегистрСведений.ЗначенияПоУмолчанию КАК Значения
|ГДЕ
|	ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА
|		ИЗ Справочник.ГруппыДоступа.Пользователи КАК ГП
|		ГДЕ ГП.Ссылка = Значения.ГруппаДоступа
|			И ГП.Пользователь = &Пользователь)"

// Хорошо: собрать независимое множество один раз, проиндексировать, соединить
"ВЫБРАТЬ РАЗЛИЧНЫЕ ГП.Ссылка КАК ГруппаДоступа
|ПОМЕСТИТЬ ВТ_ГруппыПользователя
|ИЗ Справочник.ГруппыДоступа.Пользователи КАК ГП
|ГДЕ ГП.Пользователь = &Пользователь
|ИНДЕКСИРОВАТЬ ПО ГруппаДоступа
|;
|ВЫБРАТЬ ...
|ИЗ РегистрСведений.ЗначенияПоУмолчанию КАК Значения
|	ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_ГруппыПользователя КАК Группы
|	ПО Группы.ГруппаДоступа = Значения.ГруппаДоступа"
```

## Высокие

### 5. Отбор виртуальной таблицы в ГДЕ

**Последствие:** виртуальная таблица рассчитывается целиком, индексы не
используются. **Тяжесть: высокая.**

```bsl
// Плохо
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
|ГДЕ
|	Остатки.Склад = &Склад"

// Хорошо: отбор в параметрах виртуальной таблицы
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки"
```

### 6. Отсутствие ПЕРВЫЕ N

**Последствие:** читаются все записи, когда нужна часть. **Тяжесть: высокая.**

`ПЕРВЫЕ N` всегда сопровождать `УПОРЯДОЧИТЬ ПО`: без явной сортировки выбранное
подмножество недетерминировано и отличается между прогонами и СУБД. Тест на таком
запросе проходит и падает через месяц без изменений в коде.

### 7. Непроиндексированная временная таблица в соединении

**Последствие:** сканирование временной таблицы на каждую соединяемую строку,
дорогая дедупликация в `ОБЪЕДИНИТЬ`. **Тяжесть: высокая.**

У временной таблицы по умолчанию нет индексов. Если она затем участвует в
`СОЕДИНЕНИИ`, в дедупликации `ОБЪЕДИНИТЬ` или в отборе `В (ВЫБРАТЬ ...)` по
большому множеству — создавать её с `ИНДЕКСИРОВАТЬ ПО` по ключам соединения.

```bsl
// Плохо
"ВЫБРАТЬ ... ПОМЕСТИТЬ ВТ_Ключи ИЗ &Таблица КАК Т"

// Хорошо
"ВЫБРАТЬ ... ПОМЕСТИТЬ ВТ_Ключи ИЗ &Таблица КАК Т
|ИНДЕКСИРОВАТЬ ПО
|	Номенклатура, Склад"
```

Индексировать 2-3 самых избирательных поля, а не весь список колонок:
перечисление всех полей раздувает индекс и не улучшает план.

### 8. Лишние обращения клиент-сервер

**Последствие:** сетевые задержки и сериализация контекста на каждый вызов.
**Тяжесть: высокая.**

```bsl
// Плохо
&НаКлиенте
Процедура Обработать(Команда)
	Данные1 = Данные1НаСервере();
	Данные2 = Данные2НаСервере();
	Данные3 = Данные3НаСервере();
КонецПроцедуры

// Хорошо
&НаКлиенте
Процедура Обработать(Команда)
	ВсеДанные = ВсеДанныеНаСервере();
КонецПроцедуры

&НаСервереБезКонтекста
Функция ВсеДанныеНаСервере()

	Результат = Новый Структура;
	Результат.Вставить("Данные1", Данные1());
	Результат.Вставить("Данные2", Данные2());
	Результат.Вставить("Данные3", Данные3());

	Возврат Результат;

КонецФункции
```

### 9. `&НаСервере` вместо `&НаСервереБезКонтекста`

**Последствие:** контекст формы передаётся на сервер без необходимости.
**Тяжесть: высокая.**

```bsl
// Плохо
&НаСервере
Функция ДанныеНаСервере()
	Возврат ВыполнитьЗапрос();
КонецФункции

// Хорошо
&НаСервереБезКонтекста
Функция ДанныеНаСервере(Параметры)
	Возврат ВыполнитьЗапрос(Параметры);
КонецФункции
```

### 10. `Сообщить()` вместо подсистемы сообщений

**Последствие:** сообщение не привязано к полю формы, не собирается длительной
операцией и ведёт себя по-разному в тонком, веб- и мобильном клиенте.
**Тяжесть: высокая.**

```bsl
// Плохо
Сообщить("Контрагент не указан");

// Хорошо, на сервере
ОбщегоНазначения.СообщитьПользователю(
	НСтр("ru = 'Контрагент не указан'"), , "Объект.Контрагент");

// Хорошо, на клиенте
ОбщегоНазначенияКлиент.СообщитьПользователю(
	НСтр("ru = 'Контрагент не указан'"), , "Объект.Контрагент");
```

## Средние

### 11. Лишнее РАЗЛИЧНЫЕ

**Последствие:** дополнительные проходы сортировки по тем же данным.
**Тяжесть: средняя.**

`ОБЪЕДИНИТЬ` без `ВСЕ` уже устраняет дубли по объединённому результату —
`РАЗЛИЧНЫЕ` внутри его операндов работает вхолостую. `РАЗЛИЧНЫЕ` вместе с
`СГРУППИРОВАТЬ ПО` по тем же полям избыточно так же. Когда дубли невозможны, брать
`ОБЪЕДИНИТЬ ВСЕ` и убирать дедупликацию совсем.

### 12. Отсутствие кеширования

**Последствие:** повторение дорогой операции с теми же параметрами.
**Тяжесть: средняя.**

```bsl
// Плохо
Для Каждого Строка Из ТаблицаДанных Цикл
	Курс = КурсВалюты(Строка.Валюта, Строка.Дата);
КонецЦикла;

// Хорошо
КешКурсов = Новый Соответствие;

Для Каждого Строка Из ТаблицаДанных Цикл

	Ключ = Строка.Валюта + "|" + Формат(Строка.Дата, "ДФ=yyyyMMdd");
	Курс = КешКурсов.Получить(Ключ);

	Если Курс = Неопределено Тогда
		Курс = КурсВалюты(Строка.Валюта, Строка.Дата);
		КешКурсов.Вставить(Ключ, Курс);
	КонецЕсли;

КонецЦикла;
```

### 13. Квадратичный алгоритм

**Последствие:** число сравнений растёт как произведение размеров коллекций.
**Тяжесть: средняя.**

```bsl
// Плохо
Для Каждого Строка1 Из Таблица1 Цикл
	Для Каждого Строка2 Из Таблица2 Цикл
		Если Строка1.Ключ = Строка2.Ключ Тогда
			// обработка
		КонецЕсли;
	КонецЦикла;
КонецЦикла;

// Хорошо: индекс на Соответствие
ИндексТаблицы2 = Новый Соответствие;
Для Каждого Строка2 Из Таблица2 Цикл
	ИндексТаблицы2.Вставить(Строка2.Ключ, Строка2);
КонецЦикла;

Для Каждого Строка1 Из Таблица1 Цикл
	Строка2 = ИндексТаблицы2.Получить(Строка1.Ключ);
	Если Строка2 <> Неопределено Тогда
		// обработка
	КонецЕсли;
КонецЦикла;
```

### 14. Глубокая вложенность

**Последствие:** код перестаёт читаться, правки в нём делаются наугад.
**Тяжесть: средняя.** Лечится ранним возвратом —
[architecture.md](architecture.md).

## Пакетный запрос с временной таблицей

Шаблон, к которому сводятся исправления пунктов 1, 3 и 4:

```bsl
МенеджерВТ = Новый МенеджерВременныхТаблиц;

Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = МенеджерВТ;

Запрос.Текст =
"ВЫБРАТЬ
|	Данные.Номенклатура КАК Номенклатура,
|	Данные.Склад КАК Склад
|ПОМЕСТИТЬ ВТ_Входные
|ИЗ
|	&ТаблицаДанных КАК Данные
|ИНДЕКСИРОВАТЬ ПО
|	Номенклатура, Склад";
Запрос.УстановитьПараметр("ТаблицаДанных", ТаблицаДанных);
Запрос.Выполнить();

Запрос.Текст =
"ВЫБРАТЬ
|	ВТ_Входные.Номенклатура КАК Номенклатура,
|	ВТ_Входные.Склад КАК Склад,
|	ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ
|	ВТ_Входные КАК ВТ_Входные
|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(
|			,
|			(Номенклатура, Склад) В
|				(ВЫБРАТЬ ВТ.Номенклатура, ВТ.Склад ИЗ ВТ_Входные КАК ВТ)
|		) КАК Остатки
|		ПО ВТ_Входные.Номенклатура = Остатки.Номенклатура
|			И ВТ_Входные.Склад = Остатки.Склад";
РезультатЗапроса = Запрос.Выполнить();
```

## Быстрая сверка при ревью

| Антипаттерн | Тяжесть | Что искать в тексте |
|---|---|---|
| Запрос в цикле | критическая | `Для Каждого`, внутри `Новый Запрос` |
| Реквизит через точку | критическая | `.Реквизит` на ссылке |
| Подзапрос в выборке | критическая | вложенное `ВЫБРАТЬ` в списке полей |
| Коррелированный подзапрос | критическая | `ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1` |
| Отбор виртуальной таблицы в ГДЕ | высокая | условие на поля результата виртуальной таблицы |
| Нет `ПЕРВЫЕ N` / нет `УПОРЯДОЧИТЬ ПО` при нём | высокая | большой запрос без ограничения |
| Непроиндексированная ВТ в соединении | высокая | `ПОМЕСТИТЬ ВТ_` без `ИНДЕКСИРОВАТЬ ПО` |
| Несколько серверных вызовов подряд | высокая | подряд идущие вызовы `НаСервере` из клиента |
| `&НаСервере` без нужды в контексте | высокая | серверный метод, не читающий данные формы |
| `Сообщить()` | высокая | `Сообщить("` |
| Нет кеша | средняя | повторный дорогой вызов с теми же параметрами |
| Квадратичный поиск | средняя | вложенные циклы со сравнением ключей |
| Глубокая вложенность | средняя | более 4 уровней |

Сообщать о находке стоит тогда, когда есть уверенность и признак виден в тексте.
Находка «возможно тут проблема» без признака запускает круг обсуждения, из
которого не выходит исправление.
