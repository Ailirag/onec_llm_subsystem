# Встраивание подсистемы LLM

## Состав поставки

- `cfe llm` — канонические исходники расширения.
- `cf llm` — сгенерированная обычная конфигурация-донор.
- `LLM_Subsystem.cf` — бинарный файл для стандартного сравнения и объединения.
- `manifest/llm-subsystem.json` — параметры поставки и допустимые исключения.

## Генерация

```powershell
.\tools\Test-SubsystemCoverage.ps1
.\tools\Build-EmbeddedConfiguration.ps1
```

Проверка завершается ошибкой, если объект зарегистрирован в `Configuration.xml`,
но не входит в `LLM`, дочернюю `RAG` или явный список исключений.

## Слияние с XML-выгрузкой

```powershell
.\tools\Merge-EmbeddedConfiguration.ps1 `
    -TargetConfigurationPath "C:\project\src" `
    -OutputDirectory ".build\merged-cf"
```

Скрипт сначала проверяет совпадающие имена и UUID. Одинаковое имя с другим UUID
считается конфликтом, и целевая конфигурация не изменяется. Язык с тем же именем
переиспользуется. Права подсистемы автоматически перенаправляются на корень
целевой конфигурации.

В выходной каталог не переносится `ConfigDumpInfo.xml`: после загрузки
объединённых исходников его должна сформировать платформа 1С.

## Установка через конфигуратор

`LLM_Subsystem.cf` используется как конфигурация-донор через стандартное
сравнение и объединение. Корневые свойства конфигурации-донора переносить в
целевую конфигурацию не требуется.

После объединения нужно назначить пользователям роли подсистемы, проверить
регламентные задания и заполнить настройки провайдеров. Подписки на объекты RAG
создаются отдельно в проекте внедрения.
